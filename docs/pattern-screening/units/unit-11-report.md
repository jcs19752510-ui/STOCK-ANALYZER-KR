## 4. 필요 호출 수 산정

- `PAGE_SIZE=1000`, 일 ≈2,873~2,879종목 → **일당 3페이지**.
- 목표 130거래일(2026-03-23 ~ 2026-10-01) 중 이미 25거래일(08-18~09-21)이 있어 신규 필요 ≈ **105거래일 × 3 = 약 315회**(전체 재수집 시 390회). 재시도·재개 여유를 두면 400회 이하.
- 소요 시간: `--sleep 0.3` 기준 호출 간격만 약 2분, 응답시간 포함 수 분~십수 분 수준(실측 아님, 추정).
- 일일 한도가 1,000회 이상이면 1일 내 완료 가능. **한도 확인 전 결론 불가.**

**사용자 결정이 필요한 항목**

1. **Q3 — 스팩·우선주 포함/제외**(약 186종목). 포함하면 패턴 결과에 스팩·우선주가 섞이고, 제외하려면 분류 기준과 구현 범위(`stock_master`에 종목 유형 컬럼이 없음 → 이름 패턴 필터 또는 스키마 변경)를 정해야 한다. 이 결정은 UNIT-13~16에 영향.
2. **일일 한도**: 포털 마이페이지에서 이 서비스키의 일일 트래픽 한도를 확인해 알려 주기. 약 400회가 한 번에 가능한지 판단 근거(Q1).
3. **일일 배치 스케줄러 수정 여부**: `run_daily_batch.ps1`이 `python`(3.11)을 호출해 2026-09-29부터 매일 실패 중이다. 수정은 이 기능(패턴 스크리닝)의 선행 조건이자 기존 기능 장애이지만 범위 밖이므로, 수정해도 되는지 승인 필요. (미수정 시 백필 후에도 최신 거래일이 갱신되지 않아 패턴 지표 기준일이 09-21에 머문다.)
4. 2026-08-11~08-17의 2종목짜리 5일치 행(과거 테스트성 추정)은 백필 계산에 영향이 없는지 별도 확인 대상 — 삭제 등 DB 변경은 하지 않았다.
