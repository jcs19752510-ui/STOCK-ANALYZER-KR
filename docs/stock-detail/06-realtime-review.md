# 실시간 시세(본인 전용, 증권사 Open API) 개발 가능성 검토서

- 작성일: 2026-10-06 / 상태: **검토 완료, 개발 미착수(결정 대기)** / 관련: DEC-052(개인 로컬 모드), `docs/stock-detail/04-intraday-options.md`, `docs/legal/`
- 요청(사용자): "개인 투자자·자동매매 방식(증권사 Open API REST+웹소켓, 본인 계좌 한정, 본인만 이용)으로 개발 가능하도록 전체 검토. **무조건 실시간.**"
- 결론: **기술적으로 가능하다.** 종목 상세(현재가·호가·체결·분/틱 차트·장중 조건 체크)는 웹소켓으로 진짜 실시간이 된다. 단 **전 종목 동시 실시간 스크리닝은 웹소켓 구독 한도(40건) 때문에 불가능**하고 준실시간(수 초~수십 초)만 가능하다. 서버(Render) 경유는 약관 확인 전까지 보류한다.

## 1. 확인한 사실 (출처: 한국투자증권 공식 샘플 저장소 `koreainvestment/open-trading-api`, 코드 직접 확인)
| 항목 | 확인 내용 |
|---|---|
| 접속 방식 | 웹소켓 + 접속키(`POST {base}/oauth2/Approval`, 필드 `grant_type=client_credentials`, `appkey`, `secretkey` → `approval_key`) |
| 구독 요청 | 헤더 `tr_type`(1=구독, 2=해지), `custtype=P`, `approval_key`; 본문 `{"input": {"tr_id": "...", "tr_key": 종목코드}}` |
| 수신 포맷 | 파이프(`|`) 구분 문자열, 체결통보(주문)만 암호화(AES-CBC). 서버가 보내는 `PINGPONG`에 반드시 응답해야 연결 유지 |
| **구독 한도** | 샘플 코드가 "Subscription's max is 40"으로 사전 차단 → **한 연결에서 구독(종목×TR) 합계 40건** |
| **통합시세 TR** | 체결가 `H0UNCNT0`, 호가 `H0UNASP0`, 예상체결 `H0UNANC0`, 장운영정보 `H0UNMKO0`, 회원사 `H0UNMBC0`, 프로그램매매 `H0UNPGM0`. KRX 전용 `H0ST*`, NXT 전용 `H0NX*`도 있음 |
| 지수 | 국내지수 실시간 체결 `H0UPCNT0` |
| 현재 코드 | REST 폴링만 사용하고 시장구분을 `J`(KRX)로 고정(`services/public_api/intraday/kis_client.py:46`) → NXT 시간대(08:00~09:00, 15:30~20:00) 미반영 |
확인하지 못한 것(접속 차단·원문 미열람): 약관 원문, REST 호출 한도 수치(현재 코드는 자체 간격 제한), 필드별 컬럼 순서(구현 시 샘플 코드로 확정), 동일 앱키 다중 접속 시 동작(첫 연결이 끊길 가능성 — 단일 연결로 설계해 회피), 해외(Render 싱가포르) IP 접속 가능 여부.

## 2. "무조건 실시간"의 범위 (구독 40건 한도 때문에 구분 필요)
| 화면 | 방식 | 실시간 수준 | 판단 |
|---|---|---|---|
| 종목 상세: 현재가·호가·체결·분/틱 차트 | 보고 있는 종목만 구독(체결+호가 = 2건/종목) | **진짜 실시간**(체결 즉시) | 가능 |
| 종목 상세: 조건 체크(장중) | 일봉 지표(DB) + 오늘 진행 중 봉을 서버가 계산 | 체결마다 재계산(1초 이내 갱신) | 가능 |
| 관심종목 목록 현재가 | 20종목까지 웹소켓(2건씩) 또는 REST 일괄 조회 | 실시간 ~ 수 초 | 가능(종목 수 제한) |
| **조건 스크리닝 전 종목(약 2,800)** | 웹소켓 불가(40건). REST 일괄 시세 조회로 순환 | **준실시간(수 초~수십 초)** | 제한적 가능(REST 일괄 조회 규격·한도 구현 전 확인 필요) |
| 투자자 수급 | 증권사 투자자 조회(일별). 장중 값은 시점별 잠정치로 알려져 있음(미확인) | 진짜 실시간 아님 | 시장 구조상 한계 |
→ **사용자에게 확인할 것: 어디까지를 "무조건 실시간"으로 보는지(종목 상세만인지, 스크리닝 전체인지).**

## 3. 실행 위치 비교
| 항목 | A. 내 PC(로컬 모드 확장) | B. Render 서버(소유자 전용) |
|---|---|---|
| 약관·법적 | 본인 PC·본인 계좌(일반적 개인 이용) | **서버 경유 허용 여부 미확인**(문의 필요) |
| 접속 | PC가 켜져 있어야 함, 같은 와이파이 휴대폰 가능 | 어디서나, PC 불필요 |
| 연결 안정성 | 가정 인터넷 의존 | 상시(단, 배포 때 연결 끊김·이중 연결 위험) |
| 해외 IP 문제 | 없음 | **싱가포르 IP로 증권사 접속 가능한지 미확인** |
| 키 보관 | PC `.env` | Render 환경변수(비밀) |
| 개발 난이도 | 낮음 | 중(토큰 DB 저장, 단일 연결 보장, 소유자 게이트, 프록시 시간 제한) |
**권장: 같은 코드를 만들고 설정으로 A/B를 고른다. 먼저 A로 완성·검증한 뒤, 약관 답변이 오면 B를 켠다.**

## 4. 설계안
```
KIS 웹소켓 ──(단일 연결)──▶ 수신기(재연결·PINGPONG·구독 관리) ──▶ 메모리 허브 ──▶ SSE ──▶ 브라우저(본인 한 명)
                                       │                         └▶ 분봉 집계기(틱→1분봉)   (소유자 로그인 필수)
                                       └▶ 장중 조건 체크 계산(기존 derivation 순수 함수 재사용)
```
1. **수신기**: 앱키당 연결 1개. 접속키 발급 → 연결 → 구독(`H0UNCNT0`+`H0UNASP0`) → 수신 → 파싱(파이프 구분, 컬럼은 공식 샘플 기준). 끊기면 지수 백오프로 재연결 후 구독 복구. `PINGPONG` 응답.
2. **구독 관리자**: 화면이 보는 종목만 구독(참조 카운트). 합계 40건 초과 방지, 화면을 떠나면 잠시 후 해지.
3. **허브·SSE**: 최신값은 메모리에만 보관(**디스크·DB에 틱 저장 안 함** — 재배포 위험·용량 최소화). 브라우저에는 SSE로 전송하고, 폭주 종목은 서버에서 초당 5~10회로 합쳐(coalesce) 보낸다. 15초마다 하트비트.
4. **분봉 집계**: 시작 시 REST로 오늘 분봉을 한 번 채우고(기존 코드 재사용), 이후 틱으로 현재 봉을 갱신.
5. **장중 조건 체크**: 일봉 이력(DB) + 오늘의 시가·고가·저가·현재가·누적거래량으로 기존 계산 함수를 호출. 오늘 봉은 "진행 중" 표시.
6. **시장 시간**: 통합 TR 사용. 장운영정보(`H0UNMKO0`)로 VI·거래정지·장 상태를 화면에 표시. 08:00~20:00 연결, 그 밖은 구독 해지.
7. **프런트**: `useLiveQuote(code)` 훅(EventSource, 자동 재연결). 호가·체결·차트 패널의 폴링 제거. 연결 상태 배지("실시간 연결됨 / 재연결 중 / 끊김, 마지막 수신 HH:MM:SS"). 현재가 변경 시 짧은 강조.
8. **기준 문구**: 로컬/소유자 모드에서는 "본인 증권사 실시간 시세, 본인 전용"으로 표시, 공개 화면 문구는 변경 없음.

## 5. 보안·접근 통제 (B 경로 필수, A에도 적용)
- 앱키·시크릿은 서버 환경변수에만. 브라우저·로그·응답에 절대 노출 금지(기존 규칙 유지).
- 실시간 엔드포인트는 **로그인한 소유자 아이디(지정 1개)** 만 허용, 요청마다 DB로 세션·활성·소유자 확인. 일반 회원·미로그인은 404. 기능 스위치 기본 꺼짐.
- 접속키·토큰: 증권사 토큰은 6시간에 1회 재발급 제한 → **Render에서는 DB에 저장**(파일은 재시작 시 사라짐). 접속키 로그 출력 금지.
- 연결 1개 보장: 배포 시 새·옛 인스턴스가 겹치면 이중 연결 → **DB 자문 잠금(advisory lock)으로 한 인스턴스만 수신**(배치 잠금 구현 재사용).
- 접속 한도·로그: 소유자 요청 속도 제한, 증권사 오류 메시지는 값 없이 요약만 기록.
- 이중 방어: 다른 회원에게 보이지 않는 UI + 서버 차단.

## 6. 위험과 대응
| 위험 | 영향 | 대응 |
|---|---|---|
| 약관상 서버 경유 불허(B) | 계정 제재 | 문의 답변 전 B 보류, A 먼저 |
| 해외 IP 접속 제한(B) | B 불가 | 장중 사용자 쪽 Render에서 스모크 시험으로 확인 |
| 구독 40건 한도 | 전종목 실시간 불가 | 범위 제한(§2), 스크리닝은 REST 순환 |
| 단일 연결 위반(이중 인스턴스) | 연결 끊김 반복 | 자문 잠금 + 재연결 백오프 |
| Render 프록시 장시간 연결 | 중간 끊김 | 하트비트 15초, 자동 재연결, "끊김" 배지 |
| 메모리(512MB) | 재시작 | 틱 미저장, 종목별 최신값·최근 N틱만 보관 |
| 데이터 오류(순서 뒤바뀜·중복) | 잘못된 값 | 체결 시각·순번 검증, 이상치 로그 |
| 장 시작·마감 경계 | 값 이상 | 장 상태 TR로 구분, 일봉 확정 전 표시 |
| 실제 증권사 응답은 이 개발 환경에서 시험 불가 | 현장 오류 | 모의 증권사 웹소켓 서버로 자동 시험 + 사용자 장중 스모크 시험(`kis_ws_smoke_test.py` 신규) |

## 8. 결정 필요 사항
1. 실시간 범위: (a) 종목 상세만 (b) +관심종목 (c) +스크리닝 준실시간
2. 실행 위치: A(내 PC) 먼저, B(Render)는 약관 답변 후 — 이 순서로 진행해도 되는가
3. 소유자 아이디(실시간을 볼 단일 계정)
4. 통합시세(KRX+NXT, 08:00~20:00) 사용 여부
5. 한국투자증권 앱키 발급·`.env` 입력 가능 시점(개발 착수 조건)
