# 로컬 노트북에서 최대한 빠르게 실시간 주식정보 보기 (가이드 · 계속 갱신)

전제: 본인 노트북 전용, KIS **실전** 계좌 앱키, Render 사용 안 함. 갱신: 2026-10-07 (DEC-097).
수치는 코드 기준 계산값이고, KIS 실제 한도(초당 20건은 검색 자료 기준·공식 문서 미확인)와 실제 응답 속도는 사용자 PC에서 확인해야 한다.

## 1. 한 번만 하는 준비 (순서대로)
1. 코드 받기: `git pull origin PROD_SCH`
2. `.env`(git 제외)에 실전 앱키: `LOCAL_INTRADAY_ENABLED=true`, `KIS_APP_KEY=…`, `KIS_APP_SECRET=…` (모의 키·`KIS_BASE_URL`·`KIS_ALLOW_CUSTOM_BASE_URL`은 넣지 않는다)
3. 연동 확인(읽기 전용): `py -3.12 scripts\kis_smoke_test.py`, `py -3.12 scripts\kis_daily_price_smoke_test.py` (종료코드 0이면 정상, 2면 확인필요)
4. 데이터 따라잡기 + 스케줄러 등록: `powershell -ExecutionPolicy Bypass -File scripts\fix_local_data.ps1` (마이그레이션·달력·배치·작업 스케줄러까지 한 번에)
5. 서버 재시작: `scripts\restart_local.ps1` → 브라우저 `http://localhost:4000/screener`
6. 확인: "장중 기준"이 기본 켜짐이고 배너에 `시세 수신 N/N종목`이 보이면 정상

## 2. 평소 쓰는 법 (가장 빠른 상태 유지)
- 장중(평일 08:00~20:00) 조건 스크리닝/패턴 화면을 열어 두면 시세 수신기가 자동으로 돈다. 화면을 닫고 5분이 지나면 증권사 호출이 멈춘다.
- 화면에 보이는 종목(최대 200개)은 약 3초마다, 전 종목은 한 바퀴(아래 표)마다 갱신된다. 결과 목록의 "새로 조건을 만족하게 된 종목"은 전 종목 한 바퀴가 끝나야 반영된다.
- PC를 절전으로 두지 않기(전원 연결·절전 안 함), 가능하면 유선/안정적인 Wi-Fi, Docker Desktop(DB) 켜 두기.
- 상세 화면(종목 하나)은 웹소켓 실시간 체결·호가가 따로 있다(docs/ops/local-realtime-guide.md).

## 3. 속도 조절 (`.env`에 적고 `restart_local.ps1`; 2026-10-07부터 `.env` 적용)
전 종목 2766개 = 93번 호출. 한 바퀴 ≈ 93 × `KIS_MARKET_MIN_INTERVAL`:
| 값(초) | 초당 호출 | 한 바퀴 | 20건/초 한도 대비 | 권장 |
|---|---|---|---|---|
| 0.125 (기본) | 8 | 약 12초 | 40% | 안전 |
| 0.1 | 10 | 약 9초 | 50% | **먼저 시도** |
| 0.08 | 12.5 | 약 7.5초 | 63% | 한도 확인 후 |
| 0.06 (하한) | 16.7 | 약 5.6초 | 83% | 한도 확대 계정만 |
- 일봉 보충·상세 화면 호출이 같은 한도를 나눠 쓰므로 한도의 50%를 넘기지 않는 것이 안전하다. `RATE_LIMITED`가 보이면 값을 키운다(자동으로 백오프하지만 갱신이 늦어진다).
- 우선 종목: `KIS_MARKET_PRIORITY_SECONDS`(기본 3, 최소 0.5), `KIS_MARKET_PRIORITY_MAX`(기본 200).
- 화면 계산: `LIVE_SCREEN_MIN_INTERVAL`(기본 5초), `LIVE_SCREEN_REFRESH_SECONDS`(기본 10초, 화면에서도 5~60초 선택).
- 한도 확대(최근 5영업일 평균 거래대금 조건 시 40~100건/초, 검색 자료 기준)를 받으면 0.06~0.08도 쓸 수 있다.

## 4. 느리거나 이상할 때 (빠른 점검표)
| 증상 | 원인 | 조치 |
|---|---|---|
| 배너에 "기준 일봉 … (발행 … + 증권사 보충)" | 발행 일봉이 직전 거래일보다 뒤처져 KIS 일봉으로 보충 중(정상 동작) | `fix_local_data.ps1`로 발행일을 올리면 보충이 줄어듦 |
| "일봉을 증권사에서 보충하는 중(…/…)" | 첫 계산, 캐시 없음 | 잠시 대기. 배치가 `kis_daily_bar`를 채워 두면 즉시 시작 |
| "시세를 모으는 중" | 시세 수신기 첫 한 바퀴 | 한 바퀴(약 12초) 대기 |
| 시세 수신 N이 총 종목보다 적음 | 호출 한도 초과·네트워크 | 간격을 키우고 `kis_smoke_test.py` 확인 |
| 아무것도 안 나옴 | API/DB 꺼짐 | `restart_local.ps1`, Docker Desktop |
| `[ERROR] DB is not ready` | Docker 미실행 | Docker Desktop 시작 후 재실행 |

## 5. 이 가이드가 알려주지 못하는 것 (사용자 PC에서만 확인 가능)
KIS 실제 응답 지연·실제 호출 한도, Windows PowerShell 5.1·실제 작업 스케줄러 동작, 증권사 약관(일봉 DB 캐시·본인 PC 전용 전제).
