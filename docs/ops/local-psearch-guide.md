# HTS 조건검색 연동 확인 가이드 (DEC-087) — 장중에 내 PC에서 한 번 실행

## 1. 이게 뭔가
한국투자증권 HTS(eFriend Plus)에서 **내가 만들어 "서버저장"한 조건검색식**의 결과를 Open API로 받아 보는 확인 도구입니다.
**장중에 조건 결과가 실제로 바뀌는지(종목이 들어오고 빠지는지), 얼마 간격으로 바뀌는지, 어떤 필드가 오는지**를 눈으로 확인하는 것이 목적입니다.
읽기 전용이며(주문·계좌 호출 없음) 앱키·시크릿·HTS ID는 화면에 나오지 않습니다. 이 결과를 보고 사이트에 "증권사 조건검색" 화면을 만들지와 갱신 주기를 정합니다.

## 2. 준비 (한 번만)
1. HTS(eFriend Plus) **[0110] 조건검색**에서 조건식을 만들고 **"서버저장"** 버튼을 누릅니다. (저장하지 않은 조건은 API에 보이지 않습니다.)
   - 장중 변화를 보려면 **자주 바뀌는 조건**(예: 등락률·거래량 급증)이 좋습니다. 증권사는 조건당 **최대 100건**만 줍니다.
2. 프로젝트 폴더의 `.env`에 아래 세 줄이 있어야 합니다(앱키 두 줄은 이미 있으면 그대로).
   ```
   KIS_APP_KEY=발급받은_앱키
   KIS_APP_SECRET=발급받은_시크릿
   KIS_HTS_ID=내_HTS_로그인_아이디
   ```
   `KIS_HTS_ID`는 비밀번호가 아니라 **HTS 로그인 ID**입니다. 이 ID를 채팅·메일에 올리지 마세요.

## 3. 실행 (프로젝트 폴더에서, 순서대로)
1. 조건 목록만 확인(장 시간 밖에도 가능):
   ```
   py -3.12 scripts\kis_psearch_smoke_test.py --list-only
   ```
   → `seq=0 그룹=… 조건명=…` 처럼 내 조건이 나오면 연결 성공입니다.
2. **장중(평일 08:00~20:00)** 에 관찰할 조건의 `seq` 번호로 5분간 관찰:
   ```
   py -3.12 scripts\kis_psearch_smoke_test.py --seq 0 --seconds 300 --out psearch-report.json
   ```
   - `--interval 3` : 조회 간격(초). 기본 5초, 최소 1초. 호출 한도 오류(`RATE_LIMITED`)가 나오면 늘립니다.
   - `--seq`는 여러 번 쓸 수 있습니다(최대 5개). 생략하면 목록의 첫 조건을 봅니다.
   - 중간에 `Ctrl+C`를 누르면 지금까지의 결과를 요약합니다.

## 4. 결과 읽는 법

| 화면 문구 | 뜻 |
|---|---|
| `편입 N건 … / 이탈 N건 …` | 조건 결과가 바뀐 순간(종목코드). **장중 갱신이 API로 반영된다는 증거**입니다. |
| `★ 결과가 N번 바뀜 (첫 변화 …초 뒤, 변화 사이 간격 …)` | 갱신 속도. 간격은 조회 간격보다 작게는 알 수 없습니다. |
| `응답 필드(N개): …` | 증권사가 주는 필드 이름 전체. 화면을 만들 때 쓸 값입니다. 이 줄을 알려 주세요. |
| `응답 시간: 중앙값/95%/최대` | 호출 지연. |
| `0건(오류 응답)` | 증권사는 결과가 0건이면 오류를 줍니다. 조건에 맞는 종목이 아직 없다는 뜻일 수 있습니다. |
| `100건 한도에 닿았습니다` | 조건당 100건까지만 줍니다. 조건을 더 좁혀야 합니다. |
| `[확인필요] …` | 종료코드 2. 변화가 없었거나, 장 시간 밖이거나, 호출 한도에 걸린 경우 등. 안내대로 다시 실행하세요. |
| `[실패] …` | 종료코드 1. 설정·인증 문제. 안내된 확인 항목(KIS_HTS_ID, 서버저장 등)을 보세요. |

## 5. 나에게 알려 줄 것 (비밀값은 빼고)
- 화면의 **`응답 필드` 줄**, **`★` 줄(또는 "결과가 바뀌지 않았습니다")**, **`응답 시간` 줄**, `[확인필요]/[실패]` 줄이 있으면 그 줄.
- `--out`으로 만든 `psearch-report.json`은 비밀값이 가려져 있으니 그대로 보내도 됩니다(종목코드·조건명이 들어 있습니다).
이 줄들로 갱신 속도, 필드, 한도를 확정하고 화면 개발 여부를 정합니다.

## 6. 한계
- 증권사가 서버에서 조건을 **얼마나 자주 다시 계산하는지**는 문서에 없습니다. 이 도구의 "변화 사이 간격"으로 확인합니다.
- 푸시(실시간 알림)가 아니라 **주기 조회**입니다. 즉 "몇 초마다 다시 물어봐서 바뀐 것을 확인"하는 방식의 근실시간입니다.
- 모의 서버로만 시험했습니다. 실제 응답 확인은 이 도구를 장중에 실행해야 합니다.
