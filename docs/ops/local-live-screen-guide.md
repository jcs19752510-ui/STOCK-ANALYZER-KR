# 장중 기준 스크리닝 사용·확인 가이드 (DEC-089·090) — 내 PC 전용

## 1. 이게 뭔가
조건 스크리닝(`/screener`)과 패턴 스크리닝(`/screener/pattern`)에서 **"장중 기준"** 을 켜면, 직전 거래일까지의 일봉에 **오늘 진행 중인 가격·누적 거래량**을 붙여 지표(등락률·이동평균 이격도·거래량 이상치·패턴 지표)를 **다시 계산**하고, **기존과 같은 조건식**으로 판정합니다.
내 PC(개인 로컬 모드)에서 **관리자 로그인한 나만** 볼 수 있고, 운영(Render) 사이트에는 나타나지 않습니다. 증권사 주문·계좌 호출은 하지 않습니다(시세 조회만).

## 2. 준비 (한 번만)
1. 로컬 모드와 증권사 앱키가 이미 설정돼 있어야 합니다(`LOCAL_INTRADAY_ENABLED=true`, `KIS_APP_KEY`, `KIS_APP_SECRET`). 설정 방법: `docs/ops/local-realtime-guide.md`.
2. API 서버와 웹 서버를 새 코드로 **다시 시작**합니다(`git pull` 후 `scripts\start_local_api.ps1`, `npx next dev -p 4000`).
3. 로컬에서 관리자로 로그인하면 두 스크리닝 화면에 **"장중 기준"** 스위치가 보입니다(일반 회원·운영 사이트에는 없음).

## 3. 화면에서 보이는 것
| 표시 | 뜻 |
|---|---|
| 배너 "장중 기준 · 계산 HH:MM:SS(N초 전) · 시세 수신 a/b종목 · 기준 일봉 날짜" | 이 결과가 언제, 몇 종목의 시세로, 어느 일봉 위에서 계산됐는지 |
| 경고 "거래량 계열은 장중 누적 부분값 / PER·PBR·시가총액 순위는 일봉 기준" | 장중 원천이 없는 값은 일봉 그대로이고 거래량은 하루가 끝나기 전의 부분값입니다 |
| 항목의 작은 "일봉" 표지 | 그 종목은 오늘 시세를 못 받아(또는 오래돼) 직전 거래일 값으로 계산됨 |
| "신규" 표지 / "최근 변화" | 직전 계산 대비 새로 들어온 종목 / 빠진 종목 |
| "일시정지" | 지금 결과에 고정해 페이지를 넘겨 볼 수 있음. 끄면 자동 갱신 재개 |
| "새로 계산" | 즉시 한 번 다시 계산 |
| "지연" 표시 | 갱신이 늦어지고 있음(숨기지 않고 표시) |

## 4. 처음 켰을 때 "일봉 보충 중"이 보일 수 있습니다 (DEC-090)
공공데이터 일봉은 하루 늦게 공개되어, 장중에는 발행된 일봉이 직전 거래일보다 하루 이상 뒤처지는 날이 많습니다. 이때 서버가 **증권사 일봉 조회로 빠진 날만** 종목별로 한 번씩 채웁니다(메모리에만 저장, DB 변경 없음).
- 전 종목 약 2,800개를 채우는 데 **처음 몇 분**이 걸립니다(`보충 진행 done/total`이 보임). 90%가 채워지면 결과가 나오고, 나머지는 계속 채워집니다. 하루 중 같은 날에는 다시 채우지 않습니다(서버를 다시 켜면 다시 채움).
- 증권사 일봉의 발행일 종가가 **발행 일봉과 다르면** 그 종목은 결과에서 **빠지고** 제외 수로 표시됩니다(액면분할·수정주가 어긋남 등을 잘못 계산하지 않기 위함).
- 발행 일봉이 5거래일 넘게 뒤처졌으면 재계산하지 않고 안내합니다(`LIVE_BASE_STALE`).

## 5. 내가 장중에 한 번 확인해 주세요 (실제 증권사 응답은 개발 환경에서 확인할 수 없습니다)
```
py -3.12 scripts\kis_daily_price_smoke_test.py                  # 대표 10종목 일봉 조회 + 발행 일봉(DB)과 종가 비교
py -3.12 scripts\kis_daily_price_smoke_test.py --out daily-report.json
```
- 종료 문구가 **`[정상]`** 이면 증권사 일봉이 발행 일봉과 일치하는 것입니다(종가 기준·필드 이름 확인 완료).
- **`[확인필요]`** 면 어떤 줄이 어긋났는지 그대로 알려 주세요(응답 필드 이름이 다르거나, 수정주가 기준이 다른 경우).
- 화면에서 "제외" 종목이 많거나 "보충이 끝나지 않음"이 오래가면 알려 주세요(호출 한도·지연 조정이 필요할 수 있습니다).

## 6. 설정값 (선택, `.env`)
| 이름 | 기본 | 뜻 |
|---|---|---|
| `LIVE_SCREEN_MIN_INTERVAL` | 5 | 이 초 안의 요청은 직전 계산 결과를 재사용(여러 탭이 계산을 늘리지 않음) |
| `LIVE_SCREEN_REFRESH_SECONDS` | 10 | 화면에 권장하는 갱신 간격(화면에서 5~60초로 조정) |
| `KIS_MARKET_PRIORITY_MAX` | 200 | 화면에 보이는 종목 중 시세를 더 자주 갱신할 최대 개수 |
| `KIS_MARKET_PRIORITY_SECONDS` | 3 | 우선 종목 한 바퀴 시작 간격 |

## 7. 한계 (정직하게)
- 거래량은 **장중 누적 부분값**이라 하루가 끝날 때의 값과 다릅니다(시간대 보정 없음).
- PER·PBR·시가총액 및 그 순위는 장중 원천이 없어 **일봉 기준 그대로**입니다.
- 전 종목 시세는 한 바퀴에 수십 초가 걸리는 준실시간이고, 화면에 보이는 최대 200종목만 3초 안팎으로 갱신됩니다.
- 정규장 전(08:00~09:00 시간외 시세)에는 값이 부분적일 수 있습니다.
- 이 화면은 정보를 보여 주는 도구이며 투자 권유가 아닙니다.
