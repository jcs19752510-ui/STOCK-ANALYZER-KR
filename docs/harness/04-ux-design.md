## 0. 문서 개요 및 승계 사항

이 문서는 02-planning.md v3와 03-system-design.md v3가 확정한 다음 전제를 그대로 승계하며, 재론하지 않는다.

1. **REQ-007(면책 문구 상시 노출)**: 03-system-design §6-4가 "프론트엔드 루트 레이아웃 컴포넌트 강제 노출 + `meta.disclaimer` 공통 응답 필드"로 구현 위치를 못박았다. 본 문서는 이를 **모든 화면 와이어플로우에 공통 요소로 포함**하고(§1, §2-0), 배너의 정확한 위치·크기·문구·비가역 표시 규칙까지 구체화한다.
2. **REQ-008(금지표현 가이드라인)**: "추천"/"매수신호"/"손실보전"/"수익보장" 등은 화면 어디에도 사용하지 않는다. 본 문서 §2와 §4 전체에서 실제 채택 문구를 명시하고, §2-6에 "금지 표현 → 승인 표현" 대조표를 별도로 둔다.
3. **REQ-006(데이터 기준시각 표기)**: 03-system-design §3-4의 `meta.data_freshness` 객체를 화면에 어떻게 렌더링할지 §2 각 화면과 §4 `DataFreshnessBadge` 컴포넌트에서 구체화한다.
4. **§4-3(기획서) 데이터 가공 원칙**: 원본 OHLCV를 그대로 나열하지 않는다. 화면 설계 전체가 "원본 시세 숫자를 크게 보여주는 대시보드"가 아니라 "가공된 순위/괴리율/이상치 스코어/백분위 지표를 정렬·필터링해 보여주는 도구"로 구성된다(§2-1~2-4).
5. **REQ-022(배포 게이트)**: 이 문서가 다룰 대상이 아니다. 03-system-design §7-4와 동일하게, 화면/기능으로 구현하지 않는다.
6. **REQ-016(로그인) Out-of-Scope**: 로그인/회원가입/개인화 저장 화면을 설계하지 않는다. 관심종목 저장, 즐겨찾기 등 개인화 UI 요소는 어떤 화면에도 넣지 않는다.

### 0-1. v3 개정 사항 요약 (03-system-design.md v3 확정 반영 — 가정/미확정 표시 전량 제거)

v2 시점에 이 문서 §0-1은 03-system-design.md v2 데이터 모델/API의 기술 스펙 공백 7건(Q1~Q7)을 발견해 "명시적 가정 + §7-1 확인 필요 항목"으로 분리 처리했었다. 03-system-design.md v3(§0-1, §3-1-1, §3-2, §4-2, §8-3, `decisions.md` DEC-011~016)가 이 7건을 아키텍트 직접 판단으로 전량 확정함에 따라, 본 문서도 v3에서 관련 화면 스펙 전체를 재작성해 "가정", "미확정", "옵셔널/폴백", "숨김 처리" 문구를 제거하고 정식 스펙으로 전환했다. 확정 내용 요약(상세 반영 위치는 §7-1 표 참조):

- **Q1 (market 필드 의미)**: `stock_master`/`derived_metrics_daily`/`market_summary_daily`의 `market`은 **코스피(KOSPI)/코스닥(KOSDAQ) 상장시장 구분**으로 완전히 확정됐다(`raw_ohlcv`/`market_calendar`의 `market`은 별개 차원인 거래소 세션 KRX/NXT). 종목검색·종목상세의 **시장 뱃지는 옵셔널/폴백이 아니라 정식 요소**로 확정한다.
- **Q2/Q3**: `GET /screen`에 `market`(KOSPI\|KOSDAQ\|ALL, 기본 ALL) 필터 파라미터가 추가됐고, `matched_metrics`는 "필터 조건에 쓰인 지표 ∪ `sort_by` 지표"를 항상 포함하도록 확정됐다. 스크리닝 화면에 시장 구분 필터 UI를 정식 추가한다(§2-2).
- **Q4**: `return_rank_pct`는 **"값이 작을수록 상위(고수익)"**로 확정됐다(예: 5.0 = 상위 5%). 화면 카피는 이미 이 방향성과 일치했으므로 "잠정 표기" 문구만 제거한다(§2-4).
- **Q5**: PER/PBR/시가총액은 **백분위(percentile) 방식**으로 확정됐다(`per_percentile`/`pbr_percentile`/`market_cap_percentile` 필드로 노출, 원시값 `*_raw`는 API에 절대 노출되지 않음). "PER 상위 20% 구간" 식 구간화 카피를 전부 percentile 문구로 교체한다(§2-2, §2-4).
- **Q6**: 거래대금/시가총액은 **KRW(원) 단위**로 확정됐고, API 필드명이 `total_trading_value_krw`/`trading_value_krw`/`market_cap_raw_krw`(내부 전용)로 변경됐다. 홈 화면의 억/조 단위 변환 로직 설명에 이 필드명을 반영한다(§2-1).
- **Q7**: `GET /market-summary`는 `market` 생략(또는 `ALL` 명시) 시 **서버가 직접 집계한 단일 응답**(`by_market`에 KOSPI/KOSDAQ 세부값 포함)을 반환하도록 확정됐다. 이 문서가 v2에서 임시로 설계했던 "프론트에서 코스피/코스닥 각각 호출 후 합산" 방식을 제거하고 **단일 호출 패턴**으로 전면 교체한다(§2-1).

§7-1(확인 필요 항목)은 Q1~Q7 전량 해소를 반영해 "해소됨" 상태로 갱신했으며, 이 문서 기준 잔여 확인 필요 항목은 없다(§7-1 참조). 단, `stock_master.sector`(업종 분류 데이터 출처 미확정, 03-system-design §8-2 항목8)는 Q1~Q7과 무관한 별개의 미해결 리스크이므로 그대로 부분 실패 방어 설계를 유지한다(§2-1, §7-2).

## 1. 핵심 사용자 플로우

### 1-0. 전역 구조 (모든 플로우에 공통)

```
[모든 화면]
┌───────────────────────────────────────┐
│ (스킵 링크: "본문 바로가기", 시각적으론 숨김)      │
│ [상시 고지 배너 — REQ-007, 접기/닫기 불가]        │  ← 모든 화면 최상단 고정, §2-0
├───────────────────────────────────────┤
│ [헤더: 서비스명 + 전역 내비게이션]                │
├───────────────────────────────────────┤
│                                         │
│         화면별 본문 (§2 각 절)              │
│                                         │
├───────────────────────────────────────┤
│ [푸터: 고지 전문 + 데이터 출처 + /about 링크]     │
└───────────────────────────────────────┘
```

전역 내비게이션 항목(데스크톱 상단 탭 / 모바일 하단 탭바, §6): **홈(시장 동향) · 조건 스크리닝 · 종목 검색**. "About/이용안내"는 하단 탭에 넣지 않고 푸터/배너 링크로만 노출한다(1차 내비게이션은 3개로 단순 유지 — 과설계 방지, 페르소나 P1 "짧은 시간에 핵심만"과 부합).

### 1-1. Flow A — 홈 방문 → 시장 동향 확인 (가장 빈번한 경로, 페르소나 P1)

```
[앱 최초 진입 (/)]
  → 로딩: 스켈레톤(요약 카드 3개 + 업종 리스트 5줄) 노출, 고지 배너는 즉시(스켈레톤 이전) 렌더
  → 성공: [데이터 기준시각 배지] + [전체(코스피+코스닥) 상승/하락/보합 종목 수 요약] + [총 거래대금]
          + [코스피/코스닥 개별 세부 카드 또는 탭] + [업종별 거래대금 상위] 표시
          (단일 API 호출 `GET /market-summary`의 `data`(ALL 집계) + `data.by_market`(시장별 세부)로 구성, §2-1)
  → (선택) "조건 스크리닝 바로가기" 카드 탭 → Flow B로 진입
  → (선택) "종목 검색" 카드 탭 → Flow C로 진입
  → (엣지) 배치 지연(is_latest_trading_day=false) → 요약 카드는 그대로 노출 + 배지 하단에 지연 경고 인라인 노출(비차단)
  → (엣지) 완전 실패(503 DATA_PIPELINE_STALE, 표시할 데이터 자체 없음) → Flow D로 분기
```

### 1-2. Flow B — 조건 기반 스크리닝 (핵심 기능, 페르소나 P2/P3)

```
[/screener 진입]
  → 초기 상태: 조건 입력 폼만 노출, 결과 영역은 "조건을 설정하고 [조건 적용]을 눌러주세요" 안내(빈 상태 A, 에러 아님)
  → 사용자가 시장 구분(전체/코스피/코스닥, 기본 전체)을 선택하고,
    조건(시가총액/거래량/등락률/PER/PBR) 중 0개 이상 입력, 정렬 기준 선택(선택, 기본값 등락률순)
    — 시장 구분만 선택하고 다른 조건 없이 "조건 적용"을 누르는 것도 유효한 요청이다(전체 종목을 해당 시장으로만 좁혀 조회)
  → [조건 적용] 버튼 탭
    → 클라이언트 유효성 검증(범위 오류 등) 실패 시: 해당 입력 필드 인라인 에러, 버튼은 비활성화하지 않고 제출은 허용하지 않음(포커스를 첫 오류 필드로 이동)
    → 통과 시 API 호출 → 로딩(결과 영역만 스켈레톤, 조건 폼은 그대로 유지)
  → 성공 + 결과 1건 이상: [총 N건] + 결과 리스트/카드(종목명, 조건에 쓰인 지표 값 + 정렬 기준 지표 값) + 페이지네이션
  → 성공 + 결과 0건: 빈 상태 B("조건을 충족하는 종목이 없습니다. 조건 범위를 넓혀 다시 시도해 보세요.") — 조건 폼은 그대로 남아 즉시 재조정 가능
  → 결과 항목 탭 → Flow C의 종목 상세로 이동(동일 화면 재사용)
  → (엣지) 캘린더 미확인(424) → 에러 상태 C
  → (엣지) 요청 과다(429) → 인라인 재시도 안내
  → (엣지) 서버 일시 장애(503 SERVICE_UNAVAILABLE) → 에러 상태 D, [다시 시도] 버튼
```

### 1-3. Flow C — 종목 검색 → 상세 조회 (페르소나 P1/P2)

```
[/stocks 진입]
  → 초기 상태: 검색창만 노출, 결과 영역은 안내 문구("종목명 또는 코드를 입력해 검색하세요") — 빈 상태(질의 전)
  → 검색어 입력(2자 이상, 디바운스 300ms) → 로딩(리스트 스켈레톤 3~5줄)
  → 성공 + 결과 있음: 리스트(종목명, 코드, 코스피/코스닥 뱃지)
  → 성공 + 결과 없음: 빈 상태("'{검색어}'에 대한 검색 결과가 없습니다. 종목명 또는 코드를 다시 확인해 주세요.")
  → 종목 탭 → [/stocks/{code}] 이동
    → 로딩: 헤더(종목명) 스켈레톤 + 지표 카드 스켈레톤
    → 성공: [데이터 기준시각 배지] + [지표 카드 그룹: 등락률 순위 / 이동평균 괴리율(5일·20일) / 거래량 이상치 스코어 / PER·PBR·시가총액 백분위]
    → (엣지) 신규 상장 등 결측: 해당 카드만 "데이터 부족 (상장 20영업일 미만)" 표시, 나머지 카드는 정상 표시
    → (엣지) 존재하지 않는 종목코드(404 STOCK_NOT_FOUND): 전체 화면 에러 상태 + "종목 검색으로 돌아가기" CTA
  → 뒤로가기 → 검색 결과 리스트로 복귀(스크롤 위치 유지)
```
코스피/코스닥 뱃지는 03-system-design.md v3 §3-1-1이 `stock_master.market`을 상장시장 구분(KOSPI/KOSDAQ)으로 확정함에 따라 **정식 요소**로 표시한다(v2까지의 "미확정 시 숨김" 폴백 규칙은 v3에서 제거).

### 1-4. Flow D — 데이터 갱신 실패/지연 (엣지케이스, 이 서비스 특성상 중요)

이 서비스는 배치성·+1영업일 지연 구조(REQ-011)이기 때문에, "정상 케이스만" 설계하면 실사용에서 가장 먼저 부서지는 지점이다. 03-system-design §5-4/§7-2의 장애 등급을 화면 상태로 1:1 매핑한다.

| 서버 상태 | 사용자에게 보이는 것 | 어느 화면에 적용되는가 |
|---|---|---|
| 정상 + `is_latest_trading_day=true` | 기준시각 배지만 정상 표시, 별도 경고 없음 | 전 화면 |
| 정상 + `is_latest_trading_day=false` (`staleness_note` 존재) | 데이터는 그대로 표시 + 배지 바로 아래 인라인 경고("예상보다 N영업일 지연된 데이터입니다") | 홈, 스크리닝 결과, 종목 상세 |
| `424 CALENDAR_NOT_CONFIRMED` | 전체 콘텐츠 영역을 에러 상태로 대체: "기준 거래일 계산에 필요한 휴장일 정보가 아직 준비되지 않았습니다. 잠시 후 다시 시도해주세요." (재시도 버튼) | 홈, 스크리닝, 종목 상세, 종목검색(날짜 파라미터 관련 조회 시) |
| `503 DATA_PIPELINE_STALE` (극단적 — 서빙 가능한 데이터 자체 없음) | 전체 콘텐츠 영역을 빈 상태로 대체: "표시할 데이터가 아직 없습니다. 서비스 데이터 준비 중입니다." (재시도 버튼 없음 — 데이터가 없어 재시도해도 동일하므로 "잠시 후 다시 방문해주세요" 안내로 대체) | 신규 서비스 최초 배치 실패 시 전 화면 |
| `503 SERVICE_UNAVAILABLE` (인프라 일시 장애) | 콘텐츠 영역 인라인 오류: "일시적인 오류가 발생했습니다." + [다시 시도] 버튼. 고지 배너와 겹치지 않도록 본문 영역 내부에만 표시(§5-4 설계서 요구사항 반영) | 전 화면, 개별 API 호출 단위 |
| `429 RATE_LIMITED` | 토스트/인라인 알림: "요청이 많아 잠시 지연되고 있습니다. 잠시 후 다시 시도해주세요." | 전 화면 |
| 네트워크 오류(클라이언트 오프라인 등) | 프론트엔드 자동 1회 재시도 후 실패 시 "일시적 오류, 잠시 후 다시 시도해주세요" (503과 동일 컴포넌트 재사용) | 전 화면 |

## 2. 화면별 명세

### 2-0. 공통 레이아웃(Root Layout) — REQ-007 구현의 물리적 위치

**목적**: 어떤 화면에서도 "투자자문 아님" 고지가 빠지거나 스크롤로 사라지지 않도록 구조적으로 강제한다.

**설계 결정 (비가역성 낮음이나 규제 안전 우선)**: 고지 배너는 **뷰포트 상단에 고정(sticky/fixed)**한다. 페이지 내부 스크롤과 무관하게 항상 화면에 보이게 한다. 근거: REQ-007은 9단계 보안/규제 검증에서 미반영 시 Critical 결함으로 취급되는 항목(traceability.md REQ-007 비고)이므로, "스크롤하면 안 보이는 배너"로 해석될 여지를 원천 차단한다. "예쁘지 않아도 안전한 선택"을 택한다(디자이너 페르소나 원칙).

**구성 요소**:
1. **스킵 링크**: `<a href="#main-content">본문 바로가기</a>` — 시각적으로 숨김(`sr-only`), 키보드 포커스 시 노출(§5).
2. **고지 배너(Disclaimer Banner)**:
   - 위치: 뷰포트 최상단, `position: sticky; top: 0; z-index: 최상위`.
   - 문구(고정, 절대 다른 문구로 대체 금지): **"이 서비스는 투자자문업 등록 사업자가 아니며, 제공되는 정보는 투자 조언이 아닙니다. 투자 판단과 책임은 이용자 본인에게 있습니다."** — `meta.disclaimer`(API) 값과 `copy.ko.json`의 `disclaimer.banner` 키가 항상 동일해야 한다. 프론트는 최초 렌더(API 응답 도착 전)에도 `copy.ko.json` 로컬 값으로 즉시 배너를 그린다(고지가 API 응답을 기다리며 "잠깐 안 보이는" 순간을 만들지 않기 위함).
   - 텍스트 말줄임(`...`) 처리 금지. 좁은 화면/200% 확대 시 2줄 이상으로 자동 줄바꿈 허용(배너 높이는 내용에 따라 가변, 고정 높이로 텍스트를 자르지 않음).
   - 닫기(X) 버튼 없음. 사용자가 영구적으로 숨길 수 없다(REQ-007 "상시 노출"의 직접 구현).
   - 배너 끝에 "자세히 보기" 텍스트 링크 → `/about`(§2-5)로 이동. 배너 자체 문구는 항상 동일 문장을 유지하고, 상세 설명(등록 여부, 데이터 한계, 책임 범위 등)은 `/about`에서만 확장한다.
3. **헤더**: 서비스명 워드마크(홈 링크 겸용) + 전역 내비게이션(홈/조건 스크리닝/종목 검색).
4. **`<main id="main-content">`**: 화면별 본문.
5. **푸터**: 고지 전문(배너와 동일 문장, 반복 노출로 이중 보장) + "데이터 출처: 공공데이터포털 금융위원회_주식시세정보(가공 후 제공)" + "본 서비스는 원본 시세 데이터를 그대로 제공하지 않으며, 가공된 지표만 제공합니다" + `/about` 링크.

**상태**: 이 레이아웃 자체는 로딩/에러 상태를 갖지 않는다(배너·헤더·푸터는 API 실패와 무관하게 항상 즉시 렌더되는 정적 셸이어야 한다 — 배너가 API 응답에 의존해 로딩 스피너로 대체되는 순간이 있으면 안 됨. 이는 REQ-007 강제와 직결되는 설계 원칙이다).

### 2-1. 홈 — 시장 동향 리포트 (`/`, REQ-004, REQ-006)

**목적**: "어제 시장이 어땠는지"를 가공된 요약 통계로 30초 내 파악(페르소나 P1). 원본 개별 종목 시세 나열 없음(§4-3 원칙).

**데이터 소스 (v3 — 단일 호출 패턴으로 전면 교체, Q7 해소)**: `GET /api/v1/market-summary?date=`(`market` 파라미터는 생략한다). 03-system-design.md v3 §4-2/§4-2 v3 신규 절이 확정한 대로, `market` 생략 시 서버 기본값은 `ALL`이며 응답 `data`는 다음 구조를 갖는다.

```json
{
  "market": "ALL",
  "advancers_count": 0, "decliners_count": 0, "unchanged_count": 0,
  "top_sectors_by_value": [{ "sector": "반도체", "trading_value_krw": 0 }],
  "total_trading_value_krw": 0,
  "by_market": [
    { "market": "KOSPI", "advancers_count": 0, "decliners_count": 0, "unchanged_count": 0, "top_sectors_by_value": [], "total_trading_value_krw": 0 },
    { "market": "KOSDAQ", "advancers_count": 0, "decliners_count": 0, "unchanged_count": 0, "top_sectors_by_value": [], "total_trading_value_krw": 0 }
  ]
}
```

**API 호출 1회로 코스피+코스닥 합산 요약과 시장별 세부 요약을 모두 받는다.** v2까지 이 문서가 임시로 설계했던 "코스피/코스닥 각각 명시 호출 후 프론트에서 합산"(2회 호출) 방식은 v3에서 완전히 제거한다 — 클라이언트가 부분 합으로 업종 상위 리스트 등을 재계산하며 발생할 수 있는 정확성 리스크를 서버 단일 집계로 원천 차단했기 때문이다(03-system-design §3-2/§4-2 근거).

**구성 요소(성공 상태)**:
- 데이터 기준시각 배지(`DataFreshnessBadge`, §4): "국내증권시장(KRX) 기준 2026-09-11 15:30 마감 데이터 · 2026-09-12 07:10 갱신"
- 요약 통계 그리드(`StatSummaryGrid`): 최상위 `data`(시장=ALL, 코스피+코스닥 합산)를 기본 카드로 [상승 종목 수] [하락 종목 수] [보합 종목 수] 표시(색상만으로 구분하지 않고 "+"/"-"/"0" 텍스트 기호 병기, §5). 그 아래 코스피/코스닥 탭 또는 병기 카드로 `data.by_market[]`의 개별 시장 값을 동일 형식으로 표시.
- 총 거래대금 카드: `data.total_trading_value_krw`(KRW 정수)를 억/조 단위로 변환해 "총 거래대금 12.3조원" 표시. **변환 로직**: `total_trading_value_krw`를 1억(100,000,000) 단위로 나눈 값을 "억원"으로, 1조(1,000,000,000,000) 이상이면 정수부는 "조", 나머지는 "억"으로 나눠 "12.3조원"처럼 조 단위까지 소수 1자리로 결합 표시(예: 12,300,000,000,000 KRW → 12.3조원). 코스피/코스닥 개별 거래대금도 `data.by_market[].total_trading_value_krw`를 동일 로직으로 변환.
- 업종별 거래대금 상위 리스트(`SectorSummaryList`, 최대 5개 항목, 막대바 시각화 — 막대 길이는 보조 시각 정보일 뿐, 수치 텍스트가 항상 병기됨): `data.top_sectors_by_value[].trading_value_krw`를 위와 동일한 억/조 변환 로직으로 표시.
- 진입 카드 2개: "조건 스크리닝 하러 가기"(→ `/screener`), "종목 검색"(→ `/stocks`)

**상태**:
- **로딩**: 배너/헤더/푸터는 즉시 표시, 본문은 스켈레톤(통계 카드 3개 + 업종 리스트 5줄 고정 높이 — 레이아웃 시프트 방지, CLS 최소화)
- **부분 실패(업종 데이터만 없음)**: 업종별 거래대금 섹션만 "업종 정보를 준비 중입니다"로 대체하고, 나머지(상승/하락/거래대금)는 정상 표시(`stock_master.sector` 데이터 출처가 03-system-design §8-2 항목8에서 "미확정"으로 명시되어 있음 — 이는 Q1~Q7과 무관한 별개의 승계 리스크이며, 부분 실패를 전체 화면 실패로 확대하지 않는다)
- **지연 경고**: `is_latest_trading_day=false` → 배지 바로 아래 경고 인라인 문구(아이콘 + 텍스트, 색만으로 표현 금지): "⚠ 예상보다 1영업일 지연된 데이터입니다"
- **캘린더 미확인(424)**: 본문 전체를 에러 상태로 대체(§1-4 Flow D)
- **완전 실패(503 DATA_PIPELINE_STALE)**: 본문 전체를 빈 상태로 대체(§1-4 Flow D)
- **일시 장애(503/네트워크)**: 본문 인라인 에러 + 재시도 버튼

### 2-2. 조건 기반 스크리닝 (`/screener`, REQ-003)

**목적**: 사용자가 스스로 설정한 조건으로 종목을 필터링·정렬해서 본다. **"추천"이 아니라 "사용자가 만든 조건의 기계적 결과"임을 화면 어디에도 오인 여지 없이 전달**(REQ-008).

**데이터 소스**: `GET /api/v1/screen?...`. 03-system-design.md v3 §4-2가 확정한 API 파라미터를 그대로 반영한다.

**조건 입력 폼(`ConditionFilterPanel`)** — 필드는 API가 실제로 지원하는 파라미터와 정확히 1:1로만 구성한다(지원하지 않는 필드는 만들지 않는다):

| 화면 라벨 | 입력 방식 | API 파라미터 | 비고 |
|---|---|---|---|
| 시장 구분 | 세그먼트 버튼(전체/코스피/코스닥) 3택 | `market` | 기본값 "전체"(`ALL`, v3 신규 — 03-system-design §4-2 Q3 확정). 조건이 아니라 검색 범위 필터로 취급하므로, 시장 구분만 선택하고 다른 조건 없이 [조건 적용]을 눌러도 유효한 요청으로 허용한다 |
| 시가총액(억원) | 최소~최대 범위 입력 | `market_cap_min`, `market_cap_max` | 둘 다 선택 입력, 클라이언트에서 `min ≤ max` 검증. 화면 입력 단위는 "억원"이지만 API는 KRW 정수 단위이므로, 프론트엔드가 API 호출 전 KRW로 변환한다(예: 1,000억원 → 100,000,000,000) — 03-system-design §4-1 확정 |
| 거래량(주) | **최소값만** 입력 | `volume_min` | 라벨에 "이상"만 표기(예: "10,000주 이상"), "이하" 옵션은 UI에 만들지 않음 — API 미지원 |
| 등락률(%) | 최소~최대 범위 입력 | `return_pct_min`, `return_pct_max` | 음수 입력 허용(하락 조건도 가능) |
| PER(배) | **최대값만** 입력 | `per_max` | 라벨 "이하"만 표기, 최소값 입력란 없음 — API 미지원. 내부적으로 `per_raw`(비노출 원시값)에 대한 조건이며, 응답 표시는 `per_percentile`(§2-2 결과 리스트 참조) |
| PBR(배) | **최대값만** 입력 | `pbr_max` | 라벨 "이하"만 표기, 최소값 입력란 없음 — API 미지원. 내부적으로 `pbr_raw`에 대한 조건이며, 응답 표시는 `pbr_percentile` |
| 정렬 기준 | 드롭다운(5개 값 고정) | `sort_by` | "등락률순"(`return_pct`)·"시가총액순"(`market_cap`)·"PER순"(`per`)·"PBR순"(`pbr`)·"거래량 변동성순"(`volume_anomaly_score`). 이 5개 외 값은 만들지 않음(서버가 400 처리하는 값). 기본값은 "등락률순" |
| 정렬 방향 | 토글(오름/내림) | `sort_dir` | 기본값 내림차순(desc). PER/PBR도 `sort_dir=desc`는 항상 "원시값(배수)이 큰 순"을 의미한다(백분위 방향이 아니라 실제 배수 크기 기준 — 03-system-design §4-2 v3 신규 설명 반영). 화면 토글 라벨도 "값이 큰 순/작은 순"처럼 원시값 크기 기준으로 표기해 오해를 방지한다 |

**PER/PBR/시가총액 백분위 관련 중요 고지 (v3 신규, 결과 리스트·조건 폼 공통)**: `per_percentile`/`pbr_percentile`/`market_cap_percentile`은 시장 필터(`market`)와 무관하게 항상 **코스피+코스닥 통합 전체 종목 기준**으로 계산된 값이다(03-system-design §3-2 "percentile 계산 범위 확정" 확정 사항). 즉 사용자가 "코스피만" 필터링해 조회해도, 화면에 표시되는 PER 백분위는 "코스피 안에서의 순위"가 아니라 "코스피+코스닥 전체에서의 순위"를 그대로 보여준다. 이 차이를 사용자가 오인하지 않도록, 시장 필터가 "전체"가 아닐 때(코스피 또는 코스닥 선택 시) 결과 영역 상단에 보조 안내 문구를 상시 노출한다: **"PER·PBR·시가총액 백분위는 코스피+코스닥 전체 종목 기준입니다."**

CTA 버튼 문구: **"조건 적용"**(금지어 없음). 결과 영역 제목: **"조건 충족 종목 목록 (총 {total_count}건)"**.

**결과 리스트(`ResultsTable`/`ResultsList`)**:
- 항상 표시: 종목명, 종목코드(보조 텍스트, 작은 글씨), 시장 뱃지(코스피/코스닥)
- 조건부 표시: **현재 활성화된 필터 조건에 실제로 값이 입력된 지표 ∪ 현재 선택된 정렬 기준(`sort_by`) 지표**를 컬럼/항목으로 노출한다(예: 시가총액 최소값만 넣었으면 "시가총액" 컬럼 추가, PER은 조건에 넣지 않았어도 정렬 기준을 "PER순"으로 선택했다면 "PER 백분위" 컬럼을 표시). 이는 03-system-design.md v3 §4-2가 `matched_metrics` 응답을 "(a) 실제 값이 지정된 필터 조건의 지표 ∪ (b) `sort_by`로 지정된 지표"를 항상 포함하도록 확정했기 때문이다(Q2 해소, DEC-013) — v2까지는 이 보장이 불확실해 정렬 전용 지표를 컬럼에서 제외했으나, v3부터는 항상 표시한다.
- PER/PBR/시가총액이 결과 컬럼에 포함될 때는 항상 **백분위(percentile) 값**으로 표기하며, 원시 배수/금액을 표시하지 않는다(원시값은 API 응답에 포함되지 않으므로 화면이 표시할 수도 없다). 표기 문구: "PER 백분위 상위 {per_percentile}%" / "PBR 백분위 상위 {pbr_percentile}%" / "시가총액 백분위 상위 {market_cap_percentile}%". `null`(PER·PBR 산정 불가, 예: 적자기업)인 경우 "PER 산정 불가(적자기업 등)"로 표시.
- 그 외 지표 표시 문구 규칙(§2-6 카피 가이드와 연결): "등락률 +3.2%" / "5일 이평 대비 +1.1%" / "거래량 변동성 3.2 (평균 대비 표준편차 배수)" 등, 원 수치가 아니라 항상 "무엇의 몇 배/몇 %인지"를 명시한 완전한 문장형으로 표기(단순 숫자 나열 금지 — 사용자가 원본 시세로 오인하지 않도록).
- 페이지네이션: "총 N건 중 1–50건" + 다음/이전 (page_size는 고정 50, 사용자가 조절하는 UI 없음 — MVP 단순화)

**상태**:
- **초기(조건 미적용)**: 결과 영역에 "조건을 설정하고 [조건 적용]을 눌러주세요" 안내 일러스트/텍스트. 에러 아님.
- **로딩**: 결과 영역만 스켈레톤(행 5개), 조건 폼은 그대로 조작 가능 상태 유지(폼을 잠그지 않음 — 다만 중복 제출 방지를 위해 [조건 적용] 버튼은 요청 중 로딩 스피너 표시 + 비활성화)
- **결과 0건(빈 상태)**: "조건을 충족하는 종목이 없습니다. 조건 범위를 넓혀 다시 시도해 보세요." (조건 폼 유지, 재조정 유도. "추천 조건" 같은 대안 제시 문구는 사용하지 않는다 — 이는 실질적 추천으로 해석될 여지가 있어 REQ-008 위반 소지)
- **클라이언트 유효성 오류**: 필드별 인라인 에러(예: "최소값은 최대값보다 클 수 없습니다"), 첫 오류 필드로 포커스 이동, `aria-invalid`/`aria-describedby` 연결(§5)
- **서버 검증 오류(400 INVALID_PARAMETER)**: 폼 상단 요약 배너 + 관련 필드 인라인 표시
- **424/503/429/네트워크**: §1-4 Flow D 표와 동일 컴포넌트 재사용

### 2-3. 종목 검색 (`/stocks`, REQ-001)

**목적**: 종목명/코드로 빠르게 찾아 상세로 이동하는 허브 화면.

**데이터 소스**: `GET /api/v1/stocks?query=&market=`

**구성 요소**: 검색 입력창(자동완성 아님, 디바운스 조회), 시장 구분 필터 칩(전체/코스피/코스닥 — `MarketFilterControl`, `GET /stocks?market=` 파라미터를 사용하는 정식 요소), 결과 리스트(`StockListItem`: 종목명 + 코드 + 시장 뱃지).

**상태**:
- **초기(질의 없음)**: "종목명 또는 코드를 입력해 검색하세요" 안내, 빈 상태 아이콘
- **로딩**: 리스트 스켈레톤 3~5줄
- **결과 있음**: 리스트 표시, 각 항목 탭 시 `/stocks/{code}`로 이동
- **결과 없음**: "'{검색어}'에 대한 검색 결과가 없습니다. 종목명 또는 코드를 다시 확인해 주세요."
- **에러(429/503/네트워크)**: 리스트 영역 인라인 에러 + 재시도

### 2-4. 종목 상세 — 가공 지표 요약 (`/stocks/[code]`, REQ-002, REQ-006)

**목적**: 원본 시세 대신 **가공된 지표만** 카드형으로 제공. 화면 제목·구성 자체가 "차트+표"가 아니라 "지표 카드 그룹"이어야 §4-3 원칙과 정합한다.

**데이터 소스**: `GET /api/v1/stocks/{code}/metrics?date=`

**구성 요소**:
- 헤더: 종목명 + 종목코드 + 시장 뱃지(코스피/코스닥, 정식 요소 — 03-system-design.md v3 §3-1-1 확정)
- 데이터 기준시각 배지(§2-0/§4 재사용)
- 지표 카드 그룹(`MetricCard` 5종, 원본 캔들차트/시세표 없음):
  1. **등락률 순위**: "등락률 순위: 상위 {return_rank_pct}%". `return_rank_pct`는 **값이 작을수록 상위(고수익)**로 확정된 지표다(03-system-design.md v3 §3-2, DEC-014 — 코스피+코스닥 통합 전체 종목 기준, 예: 값 5.0 = 상위 5%). 화면 카피는 이 방향성과 정확히 일치하므로 그대로 사용한다.
  2. **5일 이동평균 대비 괴리율**: "5일 이평 대비 {+/-}{ma5_gap_pct}%"
  3. **20일 이동평균 대비 괴리율**: "20일 이평 대비 {+/-}{ma20_gap_pct}%" — 결측 시 "데이터 부족 (상장 20영업일 미만)"
  4. **거래량 이상치 스코어**: "{volume_anomaly_score} (20일 평균 대비 표준편차 배수)" + 툴팁: "값이 클수록 최근 거래량이 평소 패턴에서 크게 벗어났다는 의미입니다" — 결측 시 동일 문구로 "데이터 부족" 표기
  5. **밸류에이션(PER/PBR/시가총액, 백분위)**: "PER 백분위: 상위 {per_percentile}%" / "PBR 백분위: 상위 {pbr_percentile}%" / "시가총액 백분위: 상위 {market_cap_percentile}%". 원시 배수/금액(`per_raw`/`pbr_raw`/`market_cap_raw_krw`)은 API 응답에 포함되지 않으므로 화면에도 표시하지 않는다. 세 값 모두 "값이 작을수록 상위"라는 동일한 방향성을 따르되, PER·PBR은 낮을수록 저평가=상위, 시가총액은 클수록 대형주=상위라는 산정 기준 차이가 있다 — 카드 하단에 보조 설명 텍스트로 "PER·PBR은 낮을수록, 시가총액은 클수록 상위 %가 낮게 표시됩니다"를 상시 노출해 오인을 방지한다. PER/PBR이 `null`(적자기업 등 산정 불가)이면 "PER 산정 불가(적자기업 등)"으로 표시(0이나 "-"로 대체하지 않음).

**상태**:
- **로딩**: 헤더 + 카드 5개 스켈레톤
- **성공**: 위 구성대로 표시
- **개별 지표 결측**: 해당 카드만 "데이터 부족 (상장 20영업일 미만)" 표시, 다른 카드는 정상 노출(값을 0이나 "-"로 대체하지 않음 — 03-system-design §3-2 원칙 그대로 준수)
- **404 STOCK_NOT_FOUND**: 전체 화면 에러 상태("요청하신 종목 정보를 찾을 수 없습니다") + "종목 검색으로 돌아가기" 버튼
- **424/503/429/네트워크**: §1-4 Flow D 표와 동일

### 2-5. 서비스 안내 및 면책 상세 (`/about`)

**목적**: REQ-007 배너의 짧은 문장이 담지 못하는 상세 고지(등록 사업자 아님, 정보 제공 목적, 데이터 지연 특성, 데이터 가공 원칙, 데이터 출처, 오류/피드백 채널)를 정적 페이지로 제공. 이 화면이 있어야 배너를 "짧게" 유지하는 결정이 정당화된다.

**구성 요소**: 정적 텍스트 섹션들 — (1) 서비스 정의("추천이 아니라 조건에 따른 조회 도구"), (2) 투자자문업 미등록 고지 전문, (3) 데이터 지연(+1영업일) 및 기준시각 설명, (4) "원본 시세를 그대로 제공하지 않고 가공된 지표만 제공한다"는 원칙 설명, (5) 데이터 출처 표기, (6) 문의 채널(있다면).

**상태**: 정적 콘텐츠이므로 로딩/에러 상태 없음(빌드 타임에 고정, API 호출 없음).

## 3. 디자인 시스템 원칙 (토큰)

### 3-2. 타이포그래피

- 폰트: 시스템 폰트 스택(웹폰트 로딩 없음 — 성능 목표 "모바일 3초 이내, Lighthouse 80점 이상"과 직결, 02-planning §5 KPI 승계).
- 스케일(px): 12(캡션) / 14(보조 본문) / 16(기본 본문) / 18(소제목) / 20(카드 제목) / 24(화면 제목) / 30(홈 핵심 숫자, 예: 총 거래대금). 배너 텍스트는 13px 고정(모바일 좁은 화면에서도 잘리지 않게 최소 크기 확보하되 과도하게 작지 않음).
- 행간: 본문 1.5, 제목 1.25.
- 굵기: 400(본문)/500(강조)/700(제목, 핵심 수치).

### 3-3. 간격 (4px 기준 스케일)

`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64` (px). 카드 내부 패딩 16px, 카드 간 간격 16px(모바일)/24px(데스크톱), 섹션 간 간격 32px.

### 3-4. 모양/그림자

- 라운드: 입력/버튼 4px, 카드 8px, 뱃지/칩 999px(pill).
- 그림자: 최소화(데이터 밀도가 높은 유틸리티 서비스 특성상 장식적 그림자 지양) — 카드 resting 1단계(`0 1px 2px rgba(0,0,0,0.06)`), 모달/바텀시트 오버레이 1단계만 추가.

### 3-5. 모션

- 트랜지션 150~200ms ease-out. `prefers-reduced-motion: reduce` 감지 시 모든 트랜지션/스켈레톤 펄스 애니메이션 제거(즉시 상태 전환).

## 5. 접근성 기준 (WCAG 2.1 AA 목표)

1. **색 대비**: 본문 텍스트 4.5:1 이상, 큰 텍스트(24px 이상 또는 19px 볼드 이상)·UI 컴포넌트 경계 3:1 이상 (§3-1 토큰이 이를 만족하도록 선정됨. 5단계 구현 시 실제 렌더링 결과로 재검증 필수).
2. **색에만 의존한 정보 전달 금지**: 등락률 상승/하락은 색상 + "+"/"-" 부호 + 스크린리더 전용 텍스트("상승", "하락")를 항상 함께 제공한다. 지연 경고/에러도 아이콘 모양 + 텍스트로 구분(색상만으로 구분하지 않음).
3. **키보드 내비게이션**:
   - 모든 인터랙티브 요소(검색창, 시장 구분 필터, 조건 입력, 버튼, 결과 항목, 페이지네이션)는 Tab 순서로 도달 가능해야 하며, 논리적 순서(시각적 순서와 일치)를 따른다.
   - 스킵 링크("본문 바로가기")를 페이지 최상단에 제공해, 매 페이지 배너/헤더/내비게이션을 반복 통과하지 않고 본문으로 바로 이동 가능하게 한다.
   - 모바일 바텀시트(조건 필터 패널)는 열렸을 때 포커스 트랩(Tab이 시트 내부에서만 순환) 적용, `Esc` 키로 닫기, 닫을 때 포커스를 시트를 연 트리거 버튼으로 복귀.
   - 포커스 인디케이터(`color.focus.ring`)는 모든 인터랙티브 요소에서 시각적으로 명확히 보여야 하며, `outline: none`으로 임의 제거하지 않는다.
4. **스크린리더 라벨**:
   - 모든 아이콘 전용 버튼(있는 경우)은 `aria-label` 필수(이 서비스는 원칙적으로 텍스트 라벨 병기를 우선하며, 아이콘 단독 버튼을 최소화한다).
   - 조건 입력 필드는 `<label>`을 명시적으로 연결(placeholder만으로 라벨 대체 금지).
   - 스크리닝 결과 수/로딩 완료 등 동적 변화는 `aria-live="polite"` 영역으로 공지(예: "총 32건 검색됨" — 사용자가 화면을 보지 않아도 결과 개수 변화를 인지 가능).
   - 데이터 기준시각 배지, 지연 경고, 에러 메시지, 백분위 계산 범위 고지(`InlineNotice info`)는 모두 실제 텍스트 노드로 존재해야 하며 CSS `content` 등으로 시각적으로만 표현하지 않는다(스크린리더가 읽을 수 있어야 함 — REQ-006/007 접근성 관점의 실질적 강제).
5. **폼 오류 처리**: 오류 필드에 `aria-invalid="true"` + `aria-describedby`로 오류 메시지 연결. 오류 발생 시 포커스를 해당 필드(또는 오류 요약 영역)로 이동.
6. **터치 타겟**: 모바일 인터랙티브 요소 최소 44×44px 권장(WCAG 2.5.5는 AAA이나, 모바일 우선 원칙(REQ-013)과 결합해 이 서비스는 목표로 채택).
7. **언어/구조**: `<html lang="ko">`, 시맨틱 랜드마크(`<header>`, `<nav>`, `<main>`, `<footer>`) 사용, 결과 표는 `<table>` + `<caption>`(시각적으로 숨겨도 됨) + `<th scope="col">` 사용(순수 `<div>` 그리드로 표를 흉내내지 않음, 스크린리더 표 탐색 지원).
8. **모션 민감성**: `prefers-reduced-motion` 대응(§3-5).
9. **확대/축소**: 200% 브라우저 확대 시 가로 스크롤 없이 콘텐츠가 재배치되어야 한다(반응형 원칙과 결합, §6).

## 6. 반응형/디바이스 대응 기준 (REQ-013, 모바일 우선)

**원칙**: 모바일(360~428px 기준 폭)을 1차 설계 대상으로 하고, 태블릿/데스크톱은 점진적으로 레이아웃을 확장한다(Mobile First CSS).

| 브레이크포인트 | 폭 기준 | 주요 레이아웃 변화 |
|---|---|---|
| Base(모바일) | < 640px | 1컬럼, 하단 탭바 내비게이션, 조건 필터는 바텀시트, 결과는 카드 리스트 |
| `sm` | ≥ 640px | 카드 그리드 2열(홈 요약 카드 등) |
| `md`(태블릿) | ≥ 768px | 결과 리스트가 카드에서 표(`ResultsTable`)로 전환 시작(가로 공간 확보 시), 상단 탭 내비게이션으로 전환 |
| `lg`(데스크톱) | ≥ 1024px | 조건 필터 패널이 바텀시트 대신 좌측 상시 노출 사이드 패널로 전환, 3컬럼 레이아웃 가능 |
| `xl` | ≥ 1280px | 최대 콘텐츠 폭 제한(가독성 위해 본문 최대 1200px 중앙 정렬) |

**디바이스별 세부 규칙**:
- 하단 탭바(모바일)는 고지 배너와 겹치지 않도록 화면 하단 고정, 배너는 상단 고정이므로 상호 간섭 없음. 단, 뷰포트가 매우 작은 기기(iPhone SE급, 높이 667px 이하)에서 상단 배너(2줄 확장 시)+헤더+하단 탭바가 본문 가시 영역을 과도하게 줄이지 않도록, 본문 스크롤 영역은 `min-height`를 보장하고 배너/헤더/탭바를 제외한 나머지 전체를 스크롤 가능 영역으로 확보한다.
- 스크리닝 결과: 모바일에서는 `ResultsList`(카드형, 세로 스택 — 종목명/코드 상단, 조건 지표 값들은 라벨-값 쌍으로 세로 나열), 태블릿 이상에서는 `ResultsTable`(가로 표, 각 지표가 컬럼). 두 컴포넌트는 동일 데이터를 사용하며 브레이크포인트에 따라 컴포넌트 자체가 전환된다(CSS만으로 표를 숨기고 카드를 보이는 방식이 아니라, 표 시맨틱이 필요 없는 뷰에서는 애초에 `<table>`을 렌더링하지 않는다 — 불필요한 시맨틱 마크업이 스크린리더 탐색을 방해하지 않도록).
- 이미지/차트: 이 서비스는 §4-3 원칙상 원본 캔들차트를 두지 않으므로, 무거운 차트 라이브러리 로딩이 초기 페이지 성능(3초 목표)에 영향을 주지 않는다(가공 지표는 텍스트/숫자/막대바 수준의 경량 시각화로 충분).
- 최신 모던 브라우저(Chrome/Safari/Edge 최신 2개 버전) 및 모바일 iOS/Android 최신 OS 지원(02-planning §8-A11 승계), 레거시 브라우저(IE 등) 미지원.
