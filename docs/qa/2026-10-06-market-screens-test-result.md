# 내부 테스트 결과서 — 전 종목 준실시간 시세를 스크리닝·목록 화면에 연결 (DEC-085)

- 일자: 2026-10-06 / 대상: 개인 로컬 모드(내 PC) + 로그인한 **관리자**만. 운영(Render) 빌드는 화면·요청 모두 변화 없음(시험으로 확인).
- 배포 필요: 없음(운영에서 꺼진 기능). DB 변경 없음. 푸시하면 Render가 자동 배포하지만 운영 화면은 달라지지 않는다.

## 1. 무엇을 바꿨나
| 화면 | 변화 |
|---|---|
| 조건 스크리닝 결과(표·모바일 카드) | 로컬 모드 관리자에게만 "현재가" 열(카드는 현재가 줄) 추가 + 안내문("조건 판정은 일봉 기준, 장중 값으로 다시 계산하지 않음") |
| 종목 검색 목록, 관심종목, 패턴 스크리닝 결과 | 기존 종가 요약 위에 준실시간 값으로 자동 덮어쓰기(`useQuotes` 한 곳) |
| 표시 | "실시간" 표지(값이 오래되면 "지연"), 마우스를 올리면 "N초 전 수신" |
- 코드: `frontend/src/lib/liveMarket/{merge,poller,react}.ts`(병합 규칙·조회 수명·훅), `useQuotes.ts`, `QuoteText.tsx`, `ResultsTable.tsx`, `ResultsList.tsx`, `ScreenerClient.tsx`, `globals.css`, `copy.ko.json`, `types.ts`.
- 조회 방식: 화면에 보이는 종목 코드만 `GET /api/v1/local/market/quotes`(100개씩), 주기 = 서버 한 바퀴 시간의 절반(3~15초), 탭이 가려지면 중단. 코드 목록이 바뀌면 이전 요청 취소.
- 실패 처리: 값이 없는 종목은 일 종가 요약 유지(0으로 채우지 않음). 401/403/404/503은 "쓸 수 없음"으로 굳히고 다시 묻지 않음(일반 회원은 열·안내 자체가 안 보임). 429·네트워크 오류는 간격을 늘려 재시도(상한 30초)하며 값은 "지연"으로 유지.
- **하지 않은 것(범위 밖, 의도적)**: 장중 값으로 스크리닝 조건을 다시 계산하는 일. 조건 판정은 DB의 일봉 기준 그대로이고 화면에 그렇게 안내한다. 필요하면 별도 결정·별도 설계가 필요하다.

## 3. 발견·수정한 결함
- 코드 중 `Date.now()`를 렌더 중에 읽어 React 순수성 규칙 위반(eslint) → 값을 받은 시각을 조회 쪽에서 기록하고 병합이 그 시각을 쓰도록 변경.
- Node `--experimental-strip-types`가 생성자 매개변수 속성을 지원하지 않아 시험이 실패 → 일반 필드로 변경.
- 시험 코드의 기대값 오류 1건(재시도 응답 개수)을 수정.
- 일반 회원에게 빈 "현재가" 열이 보일 수 있는 설계 문제 → 서버가 거절하면 열·안내를 숨기도록 `enabled` 판정 수정, 종단 시험으로 확인.

## 4. 확인하지 못한 것·위험
1. 실제 증권사 응답·호출 한도·2,800종목 한 바퀴 시간(앱키 없음, 접속 차단). 장중에 `/api/v1/local/market/status`의 `cycle_seconds`·`covered/total`을 확인해야 한다. 한 바퀴가 길면 "지연" 표지가 자주 보일 수 있다.
2. 처음 연 직후는 서버 폴러가 시작되어 한 바퀴를 돌 때까지 값이 비어 있다(일 종가 요약이 먼저 보이다가 바뀜). 설계에 따른 동작.
3. 한 화면에서 상세 실시간 스트림과 목록 조회가 같은 증권사 호출 한도를 나눠 쓴다(조회는 낮은 우선순위).
4. 실제 장중 값의 시가·고가·저가가 0인 경우는 미니 캔들을 그리지 않는 것으로 처리(모의로만 확인).
5. 공휴일 달력 미연동(서버 폴러 설계 한계).
