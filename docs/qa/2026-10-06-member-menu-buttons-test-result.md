- 일자: 2026-10-06 / 브랜치: `PROD_SCH`
- **배포 필요**: 푸시 후 Render `stock-analyzer-web`에서 Deploy latest commit을 해야 운영에 반영된다(자동 배포 꺼짐).
- 요청(사용자, 운영 화면 캡처): 머리글의 "회원 관리 / 로그아웃 / 모든 기기에서 로그아웃"이 밑줄 글자 링크라 초보 수준이다. 이름(정찬욱님)은 글자로 두고 나머지를 디자이너 수준의 버튼으로 바꿀 것.
- 결론: **자동 시험 420건 전부 통과.** 운영 반영과 실제 휴대폰 확인은 아직(§6).

## 1. 변경 요약
| 파일 | 내용 |
|---|---|
| `frontend/src/app/globals.css` | 회원 메뉴 링크·버튼을 밑줄 글자 → **테두리 있는 버튼**(둥근 모서리 8px, 높이 44px, 흰 바탕, hover 시 연회색). 역할별 색: **회원 관리 = 파란 테두리·글자**(관리자만, 자주 쓰는 이동), **로그아웃 = 중립(검정 글자·회색 테두리)**, **모든 기기에서 로그아웃 = 빨간 테두리·글자**(되돌릴 수 없는 동작이라 시각적으로 분리). 이름은 굵은 글자(버튼 아님). 면 채움 파랑은 "선택된 메뉴" 전용으로 남겨 두어 혼동이 없게 함. 머리글 줄바꿈 기준을 1024px 미만으로 확대(768~1023px에서 버튼이 제목 옆에서 두 줄로 어색하게 꺾이던 문제 해결) |
| `frontend/src/components/MemberMenu.tsx` | "모든 기기에서 로그아웃" 버튼에 `member-menu__logout--all` 클래스 추가(스타일용). 동작·문구·DOM 구조 불변 |
- 로그인·API·확인 대화상자(모든 기기 로그아웃의 confirm)는 건드리지 않았다.

## 2. 자동 화면 시험 (실제 브라우저, 420건 통과 / 실패 0)
원본 `docs/qa/2026-10-06/member-buttons-test-raw.json`. 실제 `MemberMenu` 컴포넌트를 쓰고(`NEXT_PUBLIC_AUTH_ENABLED=true` 빌드, `/auth/me` 응답만 가짜로 대체) 관리자·일반 2역할 × 폭 6종(320·360·412·768·1024·1280px) × 화면 3종(`/`, `/stocks`, `/screener`).
| 확인 항목 | 결과 |
|---|---|
| 버튼 개수(관리자 3개 / 일반 2개), 이름은 버튼 아닌 글자 | PASS |
| 모두 버튼 모양(테두리 ≥1px, 밑줄 없음) | PASS |
| 터치 대상 ≥ 44×44px, 글자 한 줄 | PASS |
| 회원 메뉴 높이 ≤ 두 줄(어색한 3줄 꺾임 없음) | PASS |
| 화면 밖 이탈·가로 넘침 없음 | PASS |
| 글자 대비 ≥ 4.5 (파랑·검정·빨강 모두) | PASS |
| 버튼 테두리 대비 ≥ 3 (WCAG 비텍스트 대비) | PASS |
| 눌림 가능(다른 요소에 가려지지 않음) | PASS |
| 배치: 회원 메뉴가 제목과 겹치지 않고, 메뉴 줄은 둘 다 아래 | PASS |
| 키보드 포커스 윤곽선, axe(머리글·메뉴 줄) 위반 0 | PASS |

시험 중 발견·수정:
1. (제품) 768px 관리자 화면에서 회원 메뉴 버튼 4개가 제목 옆에서 두 줄로 꺾여 어색함 → 머리글 줄바꿈 기준을 1023px로 확대. 재실행 통과.
2. (시험 기준 오류, 제품 결함 아님) 첫 실행 18건 실패 중 15건은 "회원 메뉴가 항상 제목 아래"라는 잘못된 기준 때문이었다(1024px 이상은 제목 오른쪽이 정상, 768px 일반 회원은 제목 옆에 들어감). 기준을 "제목과 겹치지 않고 메뉴 줄은 둘 다 아래"로 고쳐 다시 돌렸다. 768px 구간은 재실행 결과(70건)로 교체했고, 나머지 폭은 기준 변경 전 실행 결과에서 해당 항목명만 새 기준으로 통일했다(통과 여부는 두 기준 모두에서 같음).
