# 조건 스크리닝 화면 겹침 수정 내부테스트 결과서

- 작성일: 2026-10-03 (KST) / 브랜치 `PROD_SCH` / 접수: 사용자 캡처(`localhost:4000/screener`, 필터 입력칸이 결과 표 위로 겹쳐 보임)
- 환경: 임시 PostgreSQL 16 + 시드, 공개 API, `next dev`, Playwright(Chromium)

## 1. 원인
- 1024px 이상에서 `.screener-page__layout`은 `280px 1fr` 2열이다. 필터 열 안의 "최소/최대" 입력칸 두 개가 한 줄에 놓이는데, 입력칸이 기본 폭(약 170px)보다 줄어들지 못해(`flex: 1`만 있고 `min-width: 0` 없음) 두 칸 합계가 280px를 넘어 **오른쪽 결과 열 위로 삐져나왔다**. 결과 표에 데이터가 있을 때 겹침이 눈에 띈다(사용자 캡처). 패턴 스크리닝 화면에도 같은 부품의 접미사("이하" 등)가 넘치는 곳이 있었다.
- 사용자 화면은 브라우저 확대(주소창 돋보기 아이콘)로 CSS 폭이 1024~1100px대였던 것으로 보인다. 확대 시 폭이 좁아지는 경계 구간이라 더 잘 드러난다.

## 2. 수정(`frontend/src/app/globals.css`)
| 변경 | 효과 |
|---|---|
| `.condition-field__input`에 `min-width: 0; width: 100%` | 입력칸이 열 폭에 맞게 줄어듦 |
| `.condition-field`, `.condition-field__input-row`, `.condition-field-group__row .condition-field`에 `min-width: 0` | flex 자식이 열 밖으로 밀어내지 않음 |
| 2열 그리드를 `280px minmax(0, 1fr)`로, 그리드 자식 `min-width: 0` | 넓은 결과 표가 열을 밀어내지 않음 |
| `.quote-band__price`에 `flex-wrap: wrap` | 관심종목 별 버튼 추가로 아이콘이 3개가 된 320px에서 등락률이 밖으로 나가던 것 해소 |

## 3. 점검(`frontend/scripts/qa/layout-overflow.mjs`, 신규)

## 4. 미확인·한계
- 사용자 PC 실제 데이터(802건 결과)로 본 화면은 미확인. 같은 코드 경로지만 확인 필요.
- 이 점검은 "넘침"을 기계적으로 찾는 것으로, 정렬의 미적 판단(여백·시각 균형)은 사용자 검토가 필요하다. 이번에 지적하신 "보기 힘듦"은 겹침이 주원인으로 보이나, 필터 열이 길어 결과가 아래로 밀리는 구조 등 사용성 개선은 별도 논의 사항.
- 점검 폭은 목록의 10개 값이며 그 밖의 폭(예: 1000px)은 직접 검사하지 않았다(1024px 경계 아래는 모바일 방식 레이아웃).
