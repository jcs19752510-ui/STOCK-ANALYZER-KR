- 작성일: 2026-10-03 (KST) / 브랜치 `PROD_SCH` / 접수: 사용자 캡처의 `logs/daily_batch.log`(토요일 14:30 실행 — `[고위험 알림] Ingestion Batch가 3일 연속 실패했습니다` 와 `[대기] … 종료코드 2`가 함께 출력)
- 판정: **통과(실제 PostgreSQL 통합 테스트 포함)**. 사용자 PC 실제 스케줄러 실행은 미확인.

## 1. 문제
공공데이터포털은 영업일 다음 날에 데이터를 올린다. 금요일(10-02) 데이터는 월요일에 공개되므로 토·일에는 "대상 거래일 0건"이 정상이다. 그런데 이 실행이 FAILED로 기록되고 하루 2회 배치라 주말마다 3일 연속 실패로 집계되어 "고위험 알림"이 거짓으로 출력됐다(알림 피로 → 진짜 장애 알림이 묻힐 위험).

## 2. 수정(권장안)
| 변경 | 내용 |
|---|---|
| 기록 | 미공개 0건 실행은 계속 FAILED(재시도·따라잡기·시도 상한 동작 불변)로 기록하되 `error_summary`가 `NOT_PUBLISHED:`로 시작 |
| 집계 | `recent_ingest_statuses`가 `NOT_PUBLISHED` 접두 행과, 접두 도입 이전에 기록된 같은 사유 행(문구 "대상 거래일 데이터가 0건 반환되었습니다")을 서킷브레이커 연속 실패 집계에서 제외(백필 행 제외와 같은 방식) |
| 보완 장치 | 진짜 지연은 매일 09:10 신선도 점검(발행 거래일이 1거래일 넘게 늦으면 종료코드 1 + 웹훅)이 따로 알린다. 실제 API 오류(`API 호출 실패` 등)는 그대로 집계된다 |
| DB | 구조 변경 없음 |
