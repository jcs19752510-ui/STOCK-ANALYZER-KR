# 선발 기준 ⑪ "기관 연속 순매수" 추가 내부테스트 결과서 (DEC-061)

- 작성일: 2026-10-03 (KST) / 브랜치 `PROD_SCH` / 요청: 사용자 — "외국인 매도가 있더라도 기관이 연속 순매수하고 있다면 조건 충족. 리노공업이 좋은 예"
- 환경: 임시 PostgreSQL 16 + 시드, 모의 KIS, `next dev`(개인 로컬 모드), Playwright(Chromium). 실제 증권사 API·사용자 PC 화면은 **미확인**.

| 질문 | 사용자 선택 |
|---|---|
| 기관 연속 순매수 기준 일수 | **3일 연속** (오늘 포함) |
| ⑥(외국인+기관 20일 누적 > 0)과의 관계 | **⑥에 대안으로 추가** (둘 중 하나 충족) |
| 개인 누적이 플러스인 종목(⑦) | **기관 누적이 개인 누적보다 크면 허용** (⑪ 충족 시) |

## 2. 판정 규칙 (구현)
- **⑪ 기관 연속 순매수**: 최신 거래일부터 거슬러 기관 순매수 > 0인 날을 센다. 3일 이상이면 충족. 순매수 0 또는 순매도를 만나면 거기서 끊김(기준 미달이면 미충족). 값이 없는 날(null)을 만나면 확인할 수 없어 멈춘다(기준 전이면 산정 불가).
- **⑥ = 누적 충족 또는 ⑪ 충족** (세 값 논리합): 하나라도 충족이면 충족, 둘 다 미충족이면 미충족, 그 외(수급 일수 부족 + 연속 미충족 등) 산정 불가.
- **⑦ 예외**: 개인 20일 누적 ≤ 0이면 충족(기존). 개인 누적이 +여도 **⑪을 충족하고 기관 20일 누적 > 개인 20일 누적**이면 충족. 20일 누적은 10거래일 미만이면 산정 불가(기존).
- 화면 근거 문구에 충족 근거(누적 / 기관 연속 / 둘 다), 예외 적용 여부, 예외를 적용하지 않은 이유를 표시한다.
- 개인 로컬 모드에서만 동작(수급 데이터 출처가 로컬). DB·API·공개 화면 변경 없음.

## 4. 시험 중 발견한 점
1. **QA 간헐 실패의 원인 확인**: `new-screens-a11y`가 약 10~25% 확률로 "관심종목에 추가" 버튼을 못 찾아 실패했다. API 로그에 429가 있었고(공개 API는 IP당 분당 60회 제한), QA를 연달아 돌려 한도를 넘은 것이 원인이다. QA용 API를 `PUBLIC_API_RATE_LIMIT_PER_MINUTE=100000`으로 기동하자 **8회 연속 12/12, 429 0건**. 제품 결함이 아니라 시험 환경 문제이며 `frontend/scripts/qa/README.md`에 기록했다. (앞서 `valuation-reason`이 첫 실행에서만 실패했던 것도 같은 원인으로 **추정**되나 당시 로그를 확인하지 못해 확정은 아니다.)
2. 문구의 조사 오류("+1,585,361주이" → "주가")를 수정했다.

## 5. 한계·미확인
- 사용자의 의도("기관이 연속으로 사고 있으면")를 **3일 연속, 오늘 포함**으로 구체화한 것은 사용자가 선택한 값이다. 장중에는 당일 값이 부분 집계이므로 오늘 행이 연속 판정에 포함되어 결과가 장중에 바뀔 수 있다.
- 리노공업 사례의 이전 15일 값은 **가정값**이다(증권사 화면에는 최근 5일과 3개월 누적만 있음). 실제 20일 누적에서의 판정은 사용자 PC에서 확인해야 한다.
- 실제 KIS 응답으로 ⑪을 확인하지 못했다(클라우드에는 실계좌 키가 없음). 월요일 장중 확인 항목에 포함한다.
- 이 기준은 **개인 로컬 모드 전용**이라 공개 화면에는 나타나지 않는다. 조건 스크리닝 목록(패턴 스크리닝)의 필터로는 아직 쓰지 않는다(요청 범위 밖).
- 개별 종목 사례를 "좋은 예"로 삼은 것은 표시 기준의 설명이며, 이후 주가를 예측하거나 매수를 권하는 정보가 아니다.
