## 4. 확인하지 못한 것·위험
| # | 내용 | 대응 |
|---|---|---|
| 1 | **2027 휴장일은 공식 확정이 아니다.** 한국거래소 2027 공고는 아직 없다(통상 연말 공고). 공휴일 규정·음력(설날 2/6, 부처님오신날 5/13, 추석 9/15) 계산이고, 임시공휴일·선거일은 발표 시 추가해야 한다. 파일 머리말에 명시 | KRX 공고가 나오면 대조해 머리말 수정 후 재적재. 틀린 휴장일이 있어도 그날은 배치가 "공개 전/데이터 없음"으로 안전하게 처리하지만 화면의 "직전 거래일" 판단이 하루 어긋날 수 있다 |
| 2 | PowerShell 스크립트(`register_daily_batch_task`, `fix_local_data`, `restart_local`)는 **실제 실행을 못 했다**(Linux). 정적 점검만 통과 | 사용자 PC에서 `fix_local_data.ps1` 실행 결과로 확인. 오류가 나면 그 줄로 즉시 수정 |
| 3 | 수급 수집의 실제 증권사 응답(필드·단위·확정 시각)은 여전히 미확인 | 사용자 PC에서 `kis_smoke_test.py` 실행 후 증권사 앱과 대조 |
| 4 | 수급 스케줄이 20:10에 도는 동안 PC가 꺼져 있으면 그날 수급은 비게 된다(다음 날 20:10에 전일 행이 확정되어 채워짐) | 의도된 동작. 재실행해도 안전(멱등) |
| 5 | 가공 보류가 길어지면(구멍이 오래 안 메워지면) 그 날짜는 발행되지 않는다. 화면은 직전 발행일 그대로 | 배치 끝 경고와 `diagnose_local_data.py`가 알림. `--allow-gap` 또는 구멍 수집으로 해소 |
| 6 | 구멍 검사는 "그 날 원본 시세가 한 줄도 없는가"만 본다. 종목 일부만 빠진 부분 구멍은 기존 수집 검증(PARTIAL)이 담당 | 후속 후보: 종목 수 비율 검사 |
| 7 | 달력 방어는 시험 시점 기준이다. 2028 달력은 아직 없다 | `diagnose_local_data.py`가 달력 종료 45일 전부터 경고 |

## 5. 사용자 PC에서 한 번에 확인하는 방법
```
git pull origin PROD_SCH
powershell -ExecutionPolicy Bypass -File scripts\fix_local_data.ps1
```
달력 적재 → 진단 → 따라잡기(10/2 재시도) → 진단 → 스케줄러 3개 확인·등록까지 한 번에 한다. 마지막 날짜가 10/2로 올라가야 하고, 10/6은 10/7 14:30 이후 자동으로 채워진다.
