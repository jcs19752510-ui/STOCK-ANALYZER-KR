# 실시간 시세 백엔드·스트리밍 대행 내부 시험 결과서 (DEC-084, 1·2단계)

- 일자: 2026-10-06 / 브랜치: `PROD_SCH`
- 범위: 본인 전용 실시간 시세 중 **수신 엔진(A1)** 과 **스트리밍 API·웹 서버 대행(A2)**. 화면(A3)·전 종목 준실시간(B)·연결 확인 도구/가이드(A4)는 별도 결과서.

- 결론: **자동 시험 전부 통과(단위·통합 54건, 종단 18건, 로그인 회귀 322건).** 단, **실제 증권사 서버와의 연결은 이 환경에서 시험할 수 없었다**(§6).

## 2. 설계상 결정(근거)
- **분봉 거래량은 체결의 당일 누적 거래량 차이로 계산한다.** 체결이 일부 빠지거나 재전송돼도 봉 거래량의 합이 증권사 누적과 어긋나지 않는다. REST로 받아 둔 시작 분봉의 합과 첫 실시간 체결의 기준선이 오차(2% 또는 5,000주) 이내면 이어 붙이고, 크게 어긋나면(시간외·NXT 거래량 차이 등) 첫 체결의 누적−체결량을 기준선으로 써서 거래량 폭증을 막는다.
- **틱은 저장하지 않는다**(메모리만). 재배포·용량·약관 위험을 줄인다.
- **한 연결 구독 한도 40건 = 종목 20개**(체결+호가). 초과는 429.
- **소유자(관리자)만**: 개인 로컬 모드 4중 통제 + 로그인을 켠 환경은 요청마다 DB에서 "유효한 세션+활성+관리자"를 확인하고, 스트림이 이어지는 동안 5분마다 재확인(권한 회수·로그아웃·사용 중지를 반영). DB 연결은 확인 직후 반납한다.
- 증권사 웹소켓 주소는 `ws://`(암호화 없음, 증권사 공식 규격). 접속키는 메모리에만 두고 로그·오류 메시지에 싣지 않는다.

## 5. 보안 점검
- 접근 통제 4중(스위치·허용 IP·프록시 헤더 없음·사설 Host) + 관리자 확인(요청 시·스트림 중). 미충족은 존재를 숨기는 404, 권한 없음은 403.
- 웹 서버 대행은 쿠키·인증 헤더를 API로 넘기지 않고 내부 토큰만 사용. 브라우저가 연결을 닫으면 API 연결도 닫음.
- 앱키·시크릿·접속키는 응답·로그에 없음(오류 메시지는 종류와 짧은 설명만). 접속키 발급 실패 시험에서 시크릿 미노출 확인.
- 증권사 접속 주소는 설정 모듈이 실전 주소만 허용(오설정·SSRF 방어), 모의는 명시적 허용 때만.
- 알려진 위험: 증권사 웹소켓이 평문(`ws://`)이다. 공개 와이파이에서 쓰지 않는다(가이드에 명시 예정).
