# 자동 배포(`PROD_SCH` 푸시 → 서버 자동 반영) 내부테스트 결과서 (DEC-062)

- 작성일: 2026-10-03 (KST) / 브랜치 `PROD_SCH`
- 요청: 사용자 — "PROD_SCH에 git push 할 때 바로 반영되길 원합니다. 기존 배포/검증 방식은 번거로워서 빼려고 합니다. 변경이 가능한지 검토해 주세요."
- **한계(먼저 읽어 주세요)**: 클라우드 개발 환경에는 Docker 엔진과 실제 서버가 없어, 아래 시험은 **가짜 `docker`·`curl`과 임시 git 저장소**로 스크립트의 판단·흐름을 실행한 것이다. 실제 Docker 빌드, 서버의 cron 환경, GitHub 배포 키 접속은 시험하지 못했다.

## 1. 검토 결론
가능하다. 기존 `deploy.sh`(백업 → 빌드 → DB 갱신 → 재시작 → 실패 시 롤백)를 그대로 쓰고 **"배포를 시작하는 방법"만** 바꿨다.

| 항목 | 변경 전(DEC-060) | 변경 후(DEC-062) |
|---|---|---|
| 운영 브랜치 | `release`(신설) | `PROD_SCH` |
| 시작 | 병합 → 자동 검사 → 사람 승인 → GitHub Actions가 SSH로 배포 | 서버 cron(2분)이 `PROD_SCH` 새 커밋을 확인해 배포 |
| 사전 검증 | 린트·테스트·빌드 | 제거(사용자 결정) |
| 안전장치 | 승인, 검사, 백업, 롤백 | 백업(실패 시 취소), 상태 확인, 자동 롤백, 일시 정지 |
| GitHub 설정 | `production` 환경·승인자·Secrets 4개·`DEPLOY_ENABLED` | **없음**(서버의 읽기 전용 배포 키만) |
| SSH 22번 | Actions 접속을 위해 공개 필요 | **내 IP만 허용 유지**(서버가 밖으로 읽기만 함) |

## 2. 사용자 결정(질문 4건)
반영 방식 **A 서버 폴링** / 안전장치 **백업 + 상태 확인 + 자동 롤백** / 배포 대상 **코드 변경 푸시만** / **상시 승인으로 기록**.

## 3. 구현
- `deploy/scripts/auto-deploy.sh` (신규): 자체 잠금, 원격 `PROD_SCH` 확인(`git ls-remote`) → 실행 중인 커밋과 비교 → 바뀐 파일 경로 필터 → `deploy.sh` 호출. 실패한 커밋은 재시도하지 않음. `--status/--pause/--resume/--retry/--help`. 선택적 웹훅(`AUTO_DEPLOY_WEBHOOK_URL`).
- `deploy/scripts/deploy.sh`: 기본 브랜치 `PROD_SCH`, 다른 배포가 진행 중이면 종료코드 **75**, 성공 시 배포한 커밋 전체 SHA를 `.deployed_sha`에 기록.
- `deploy/crontab.example`에 2분 주기 줄, `.env.production.example`에 웹훅 변수, `.gitignore`에 상태 파일 4개.
- 삭제: `.github/workflows/deploy-production.yml`.
- 문서: 절차서 §7·§9·§11~§16 개정, DEC-062, 사전 체크리스트 문구.

### 4-1. 시험 중 발견·수정한 결함
1. **웹훅 JSON 깨짐**: 알림 문구에 **탭 같은 제어 문자**가 있으면 JSON이 유효하지 않았다(처음 시험은 이를 걸러내지 못할 정도로 느슨했음). 제어 문자 제거·이스케이프를 추가하고 시험을 엄격하게 고쳤다.
2. 시험이 형식적으로 통과하는지 확인하려고 **변이 시험**을 했다: ① 필터 제거 ② 실패 커밋 재시도 허용 ③ 잠금 충돌을 실패로 처리 ④ 일시 정지 무시 ⑤ 탭 이스케이프 제거 — **5가지 모두 시험이 실패로 감지**했다.

## 5. 위험과 완화 (사용자가 상시 승인으로 선택)
| 위험 | 완화 | 남는 위험 |
|---|---|---|
| 푸시한 코드가 승인 없이 운영 반영 | 상태 확인 + 자동 롤백, 일시 정지 명령 | 고장 난 코드가 **빌드·기동만 되면** 올라감 |
| GitHub 쓰기 권한 = 서버 코드 실행 | 2단계 인증, 권한 최소화, 서버 배포 키는 읽기 전용, 컨테이너 권한 최소화(`cap_drop`, `read_only`) | 계정·토큰이 뚫리면 운영 코드가 바뀜 |
| DB 마이그레이션 자동 적용 | 배포 전 백업(실패 시 취소) | 자동 롤백은 **DB 구조를 되돌리지 않음** |
| 문서·QA 푸시마다 재배포 | 경로 필터 | 목록에 없는 새 파일은 배포 쪽(안전 우선) |
| 빌드 중 서버 부하 | 2분 주기, 같은 커밋 재시도 없음 | 빌드 몇 분간 느려질 수 있음 |
