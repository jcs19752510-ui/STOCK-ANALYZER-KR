## 3. 발견·수정한 결함
- 제품 코드의 결함: 브라우저 시험에서 발견된 것은 없다. 작성 중 스스로 고친 것: 낭독용 상태 영역을 내용과 함께 새로 붙이면 첫 안내가 읽히지 않으므로 화면 최상위에 항상 두도록 변경.
- 시험 코드 결함(제품 아님) 3건 수정: SSR 검사 정규식이 기존 `/screener`의 자체 `<select>`를 오탐 → 화면 고유 요소로 한정 / live 영역 검사가 Next 경로 안내기(`div[aria-live=assertive]`, `main` 밖)를 세어 실패 → 본문(`main`)으로 한정(전체 목록도 함께 기록) / Tab 순서 검사를 0건 상태에서 해 실패 → 표가 있을 때로 이동. 순수 로직 시험 1건은 기대값 오류(다른 조건 응답에 seq 불일치 기본 응답 사용)를 수정.

## 4. 확인하지 못한 것
1. 실제 증권사 응답·실제 백엔드·로그인을 켠 웹 서버 대행(BFF) 경로 — 메인이 합친 뒤 종단 시험 필요. 가짜 서버는 계약서 모양만 흉내 낸다(필드명 불확정 부분, 실제 `changes`·`entered_at` 의미 포함).
2. 서버 재기동 직후에는 서버가 모든 종목을 "처음 본 것"으로 세므로 최대 60초간 전 종목에 "신규"가 붙는다(계약서 §4 그대로). 실제로 어떻게 보이는지는 실서버로 확인하지 못했다.
3. 다크 모드는 앱에 다크 테마가 없어 시험 대상이 아니다(토큰만 사용). 실제 스크린리더(NVDA·VoiceOver) 낭독은 듣지 못했고 axe·구조 확인만 했다. Chromium만 사용(다른 브라우저 없음).
4. 장시간(수 시간) 연속 열어 둔 동안의 메모리·누수는 보지 않았다.

## 5. 계약서와 다르게 한 점 / 요청 변경 목록
- 계약 모양·오류 코드는 그대로 따랐다. 추가로 **401도 403·404·503과 같이 "다시 묻지 않음"**으로 처리(`liveMarket`과 동일, 로그인 없음은 재시도해도 같음). 400 `INVALID_SEQ`는 같은 조건으로 재시도하지 않고 멈춘다(조건을 바꾸면 풀림). 502(`PSEARCH_REJECTED`·`UPSTREAM_UNAVAILABLE`)는 재시도(백오프) 대상.
- 요청 1(메인·백엔드): `PSEARCH_NOT_CONFIGURED`(503)면 계약상 전환 항목이 숨겨져 관리자가 안내 화면(KIS_HTS_ID)에 직접 주소로만 도달한다. 항목을 보이게 하려면 계약 §5의 "503이면 항목 없음"을 "PSEARCH_NOT_CONFIGURED는 예외"로 바꿔야 한다. 지금은 계약대로 숨김.
- 요청 2(기존 `liveMarket`, 수정하지 않음): 종목 코드 목록이 바뀔 때 `LiveMarketPoller.setCodes`가 시세를 비워 잠깐 "-"가 된다. 이 화면은 마지막 값을 "지연"으로 이어 보여 가렸지만, 근본적으로는 이전 값을 유지하는 편이 낫다.
- 요청 3(백엔드): `entered_at`을 서버 재기동과 무관하게 보존할 수 있으면 "신규"가 더 정확해진다(필수 아님).

## 6. 위험
- 가짜 서버 기준 시험이라, 실제 응답에서 `name`·`market`이 자주 null이면 표에 코드만 보이는 행이 많아진다(동작은 확인됨).
- 조회 간격이 서버 캐시(`cache_ttl_seconds`)에 의존한다. 서버가 잘못된 값을 주면 5~60초로 보정되며 그 밖은 믿지 않는다.
- 전환 항목 확인은 화면 로드마다 조건 목록을 1회 요청한다(서버 60초 캐시, 같은 순간 중복은 합침). 일시 오류(429·502·네트워크)는 항목을 숨기고 다음 화면 로드에서 다시 확인한다.
