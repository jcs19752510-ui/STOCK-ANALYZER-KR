## 3. 발견·수정한 결함
1. (백엔드) HTS ID가 요청 주소(쿼리)에 들어가 httpx 로그에 기록될 수 있음 → 로거 필터로 가림, 시험으로 고정.
2. (메인 보강) 증권사 **HTTP 장애를 0건(전부 이탈)으로 오인**할 수 있음 → `KisError.http_status` 추가, HTTP 200의 업무 거절만 0건으로 보고 장애는 이전 결과를 `stale`로 유지. 회귀 시험 2건.
3. (메인 보강) `KIS_HTS_ID` 미설정 관리자는 전환 항목이 숨겨져 설정 안내 화면에 닿을 수 없음 → 503 `PSEARCH_NOT_CONFIGURED`만 예외로 항목을 보임(앱키 없음 등은 계속 숨김). 계약서 §5와 시험 갱신.
4. (화면) 낭독 상태 영역을 항상 화면 최상위에 두도록 수정, 시험 코드 결함 3건 수정(제품 결함 아님).
5. 종단 시험 보조: 모의 증권사 조건검색 종목코드를 `MOCK_PSEARCH_CODE_PREFIX`(기본 없음=숫자 코드)로 DB 시험 데이터(T00001…)와 맞출 수 있게 함.

## 4. 확인하지 못한 것·위험 (정직한 한계)
1. **실제 증권사 응답**: 필드 이름(공식 샘플은 23개 정의), 0건 응답 문구, **장중 갱신 주기와 실제로 결과가 바뀌는지**, 호출 한도 — 장중 사용자 PC에서 `kis_psearch_smoke_test.py`로만 확인 가능. 결과가 "바뀌지 않음"으로 나오면 이 화면의 가치가 줄어든다.
2. 0건 응답과 조건 키 오류는 같은 코드(HTTP 200, rt_cd≠0)일 수 있다 → 화면이 증권사 문구를 그대로 보여 준다.
3. 편입 시각·변화 기록은 서버 메모리라 서버를 재기동하면 처음 본 시각부터 다시 센다(재기동 직후 60초간 전 종목에 "신규"가 붙을 수 있음).
4. 조건 20개 이상 동시 조회 시 호출 한도, 다중 프로세스, 실제 스크린리더 낭독, Chromium 외 브라우저는 시험하지 못함.
5. 이 화면은 증권사가 판정한 결과를 **표시**할 뿐 사이트가 조건을 재계산하지 않는다(DEC-085와 같은 원칙). 장중 재계산(사이트 자체 판정)은 보류 상태.
